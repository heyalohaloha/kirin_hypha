## 1. Hypha が取り組む対象

SPACE の追加機能は、「選んだ音の立ち上がりから、その後のエネルギーがどう消えるかを観察し、処理前後や Reference と比較する道具」として設計することを提案する。
残響の種類、部屋の大きさ、音源の前後位置を自動判定する機能にはしない。
ミックス済み音声では楽器の減衰、フェード、残響が同じ包絡線に現れ、それらを今回の入力だけで分離できないためである。

利用者が答えを得られる問いは、次の三つに絞る。

1. 選んだイベントでは、最初の 80 ms と、その後 250 ms までのエネルギーはどのような比率か。
2. 条件を満たす観測区間では、包絡線はどの程度の速さで下がっているか。
3. 同じイベントの同じ観測条件で PRE と POST を比べると、その比率や減衰がどう違うか。

既存 SPACE の FIELD、CORRELATION、L/R BALANCE は維持する。
FIELD は左右関係、追加する DECAY subview は音の消え方を扱い、同じ図形へ二つの意味を重ねない。
TIME の連続履歴を複製せず、SPACE では選択したイベント、その観測区間、比較可能な候補群を読む。

## 2. SPACE の最初の製品化候補

最初の候補は広帯域の EARLY と DECAY、および条件を満たす PRE/POST 差分とする。
POST 単体でも観測できるが、PRE がないときに差分を絶対値へ無言で置き換えない。
PRE は正確な POST request に応じる測定側として対応し、PRE に新しい操作ページを増やすことは今回の推奨範囲に含めない。
共通の文字、状態表示、Capture の整合性は PRE と POST の両方を確認する。

| 対象 | 計画上の扱い | 製品として主張する範囲 |
| --- | --- | --- |
| EARLY | 最初の試作と製品化候補 | 指定した二つの有限窓のエネルギー比 |
| DECAY | 最初の試作と製品化候補 | 条件を満たす包絡線の減衰率と、その回帰換算時間 |
| EARLY の分布 | 詳細画面の観測事実として評価 | 採用イベント間のばらつき。奥行きとは呼ばない |
| DEPTH | 現定義の製品化は非推奨 | 奥行きの指標としての妥当性を別に実証しない限り使わない |
| REPEAT | 独立した研究候補 | 反復周期の候補。ディレイの存在や追加量とは断定しない |
| 帯域別 DECAY | 広帯域で有用性を確認した後の採否候補 | 定義済みの帯域パワーの減衰。表示 PSB は入力にしない |
| Reference 比較 | 同じ測定定義と source 検証を満たして接続 | 同曲の対応区間比較と、別曲の分布比較を区別する |

これは優先順位の提案であり、DEPTH や REPEAT を承認なしに後工程へ移す決定ではない。
広帯域の差分が成立しない場合に、POST 単体版だけを先に公開することも自動では決めない。

## 3. 測定値の定義案

### EARLY の窓とチャンネル

EARLY は `10 log10(E_early / E_late)` とし、窓は半開区間 `[t0, t0+80 ms)` と `[t0+80 ms, t0+250 ms)` に固定する案を推奨する。
共有境界のサンプルを二重に数えず、ms からサンプルへの丸め規則を定義の一部にする。
丸めの推奨案は、非負の相対時刻について `q(ms) = floor((sample_rate × ms + 500) / 1000)` とし、各境界を native sample の起点へ一度だけ加える方式である。
10 ms ごとの包絡線境界も起点から直接求め、丸めた一窓の長さを繰り返し加算しない。
負の DAW 起点は維持し、積と加算の overflow、半開区間の終端、異なる block 分割を検証する。
mono は一チャンネルの二乗値、LR は各チャンネルの二乗値を平均して積算し、L と R を加算してから二乗しない。
これにより、同相と逆相の違いをエネルギーの消失と取り違えない。

片方の窓が未完了、欠測を含む、またはエネルギーが定義した測定下限を満たさない場合は数値を出さない。
分母に便宜的な微小値を足して巨大な有限値へ変換しない。
一定パワーなら窓長の違いから約 −3.2736 dB になるため、0 dB を中立値として着色しない。
表示名は `EARLY 80/250` とし、直接音／残響比や標準の C80 と同一視しない。

250 ms 内の別 onset は EARLY の数式を無効にはしないが、単一イベントの消え方という解釈には影響する。
推奨案は、次 onset が窓内にある候補へ重なりの事実を付け、単発候補の集計と混ぜないことである。
別 onset の検出漏れがないとは保証せず、重なり判定の定義と分類別 coverage を測る。
この分類を変えても、固定起点の EARLY 積算値自体を変更しない。

### DECAY の時間と傾き

最初の試作では、10 ms の非正規化パワー包絡線を dB に変換し、連続した有効区間に対する傾き `s [dB/s]` を観測する。
負の傾き、十分な観測点、実際に観測した減衰幅、測定下限からの余裕を必須とし、直線への適合度はそれらとは別に記録する。
次 onset までを自動的に自由減衰区間と見なさず、再上昇、次の音、欠測で分断された区間をつなぎ直さない。

UI の主値は **20 dB 相当時間** `D20 = 20 / |s| [s]` とする案を推奨する。
これは選択区間の回帰から換算する量であり、実際の閾値通過時刻の差や標準の T20 ではない。
標準の T20 は 20 dB 区間から求める RT60 の値なので、名称を流用しない。[REW 公式の定義](https://www.roomeqwizard.com/help/help_en-GB/html/graph_rt60.html)
`DECAY 20 dB` と「回帰換算」で意味を明示し、傾き、区間長、観測した dB 幅を詳細表示に残す。

この案では、少なくとも 20 dB の実測幅がある区間だけから D20 を出す。
短い観測から 60 dB の時間へ外挿した値を、意味の説明なしに主値へ置かない。
元提案の秒表示とは定義が変わるため、採用には Daisuke の承認と新しい定義 ID が必要になる。
試作ログには元提案の `60 / |s|` も比較用に保存できるが、製品へ二つの「秒」を同時に追加することは推奨しない。

回帰方式、区間の開始規則、測定下限、適合度の閾値は開発用素材で比較してから固定する。
最低 10 点は試作開始時の条件案とし、それだけで精度を保証しない。
保持を 6 秒に制限する場合も、それは取得できる観測区間の上限であり、換算時間の値域と別に扱う。
ドライな指数減衰音でも値が成立することは、この定義では正常である。

包絡線の各点は、その sample 区間の平均パワーと実時刻を持つ。
窓幅が一 sample 異なる場合も平均化し、回帰の横軸へ単なる配列 index を使わない。
ノイズ床に達した値や保持上限で切れた区間を、完全な減衰として延長しない。
候補ごとに都合のよい直線区間を探し続ける選択偏りを防ぐため、開始点、終端、再上昇、floor、回帰方式、棄却の優先順を定義 ID に含める。

## 4. 2MIX への適用範囲

### 4.1 現行 ATTACK の対象を常に表示する

現行 ATTACK は DRUM 向けの設定で動き、2MIX は独立した適格性確認を要する契約である。
これは文書上の注意だけではなく、`attack_runtime_worker.rs` が `drum_config` を選ぶ実装にも対応している。
既存 onset 列があることを、完成済み楽曲に使える根拠として扱わない。

現行の画面には、幅と pair 状態によって `DRUM` が表示されず、`POST` だけになる箇所がある。
計画では `ATTACK / DRUM` を計算方式の識別として全サイズで明示し、PRE／POST／Δ と LIVE／固定の状態は別に表示する。
ヘルプ、空状態、Capture、accessibility にも DRUM の対象範囲を含める。
この表示整理で DRUM の検出器、係数、既存イベントの意味は変えない。

### 4.2 TRACK／STEM と解析 profile を分ける

TRACK／STEM と 2MIX は「何を見ているか」の利用文脈、DRUM と ATTACK 2MIX は「どの定義で解析するか」の区分とする。
既存の context control はメーターの利用文脈を切り替えるものであり、その表示が 2MIX であることは 2MIX 専用検出器が動いている証拠にならない。
トラック名、bus 名、音の自動分類から解析方式を決めない。

| 利用文脈と素材 | 推奨する ATTACK の入口 | 適用範囲 |
| --- | --- | --- |
| TRACK／STEM の drum または percussion | `ATTACK / DRUM` を明示して選択 | 現行の DRUM 定義を使う |
| TRACK／STEM の vocal、strings、pad など | 汎用 ATTACK があるとは表示しない | TRACK／STEM だから DRUM が適合するとは扱わない |
| 2MIX の完成ミックス | 合格した `ATTACK / 2MIX` を明示して選択 | DRUM を代用せず、独立した定義を使う |

DRUM の入口を TRACK／STEM 側へ置く案を推奨するが、これは画面配置の承認候補とする。
2MIX 側へ移った際に、表示だけを変えて DRUM を動かし続けない。
profile と文脈が不整合になる操作では旧 request を終了し、次の profile の明示選択まで取得待ちにする案を推奨する。
文脈の切替だけで Record、pair 選択、Meter Session をリセットしない。

2MIX 用が合格するまでは、その実行入口を公開しない。
現在の DRUM が 2MIX にも対応しているように見せず、将来機能の空ボタンを既成の機能として置かない。
未分類の一般 TRACK／STEM 用 profile を追加する場合は、DRUM と 2MIX のどちらかを改名せず、別の提案として対象を定義する。

### 4.3 ATTACK 2MIX を独立して開発する

2MIX 用 ATTACK は SPACE の補助機能だけでなく、完成ミックス内の知覚可能な立ち上がりと、処理前後での変化を読む機能として完成させる。
楽器の note-on を全部数える検出器や、drum stem を抽出する機能とは区別する。
既存の DRUM／2MIX 二 profile 方針を出発点とし、DRUM の成績や係数を 2MIX の合格根拠には使わない。
古い復旧計画の「未実装」という状態記録を、現在の DRUM の状態へ読み替えることもしない。

| 作業 | 成果物と確認事項 |
| --- | --- |
| A0 対象と入口の整理 | 常時見える DRUM 表示、TRACK／STEM と 2MIX の配置、対象外素材の説明、全サイズの操作契約 |
| A1 音声と評価器 | 2MIX 専用の素材台帳、独立した音声注釈、開発用／未使用評価の分離、event の意味と一対一対応規則 |
| A2 検出器の選定 | 2MIX 専用の係数、窓、peak rule、尺度、定義 ID。vibrato、持続音、複合音、密なマスターの診断 |
| A3 比較と表示 | PRE も同じ profile で測る exact pairing、POST 単体、符号付き差分、詳細の確定、固定と再開、Capture |
| A4 製品適格性 | 未使用評価、処理変換試験、2 オーナー、音声素通し、macOS／Windows、実際の読解と聴取 |

第一候補は、既存計画の fixed-scale SuperFlux 系とする。
SuperFlux は vibrato による誤検出を抑える研究上の根拠を持つが、論文の成績を Hypha の 2MIX 合格証拠にはしない。[Böck と Widmer の原論文](https://phenicx.upf.edu/system/files/publications/Boeck_DAFx-13.pdf)
DRUM と analyzer のコードを共有できても、係数、public scale、定義 ID、評価素材、合否は独立させる。
DRUM と 2MIX の Onset Flux 数値を、そのまま相互比較できるとは表示しない。

評価器は MIDI を正解とする DRUM 用の仕組みを転用せず、二人の注釈者が候補出力と MIDI を見ずに完成音声を聴いて作った event を使う。
既存計画の 2MIX 専用開発／評価素材、各 20 本の 30 秒抜粋、独立注釈という構成を最低の出発点として再確認する。
合成ベースの素材だけで一般の完成マスター全体を保証せず、権利確認済みの実ミックス、マスター、密度、音色を補完した試験を候補固定前に設計する。
古い資料に「未開封」と書かれていても、現在の取得履歴を確認せず新しい holdout と呼ばない。

2MIX の合格値は既存の一般 gate を下げない。
Precision 0.85以上、Recall 0.75以上、F1 0.80以上、timing absolute error P95 15 ms以下、FP 1回／秒以下、signed timing median の絶対値は48 kHzの一 hop以下を出発点とする。
pooled 値だけでなく規定の全 fold、二つの注釈集合、各処理変換を個別に確認し、平均成績で失敗条件を隠さない。
kick-only と hat-only の専用 gate は DRUM 用であり、2MIX の合否へ機械的に移さない。
annotation 間 F1 0.90以上という既存条件、対応許容幅、独立評価の手順も含め、既存の評価契約との差分を A1 で固定する。
注釈者間で成立しない event 定義は、検出器の調整へ進む前に対象と境界を見直す。
二人の注釈者の確保は必要な外部依存であり、AI が作ったラベルだけで人による一致条件を通したとは扱わない。

PRE/POST の identity、固定 gain、EQ、fast／slow compressor、lookahead limiter、既知／不明な遅延を別々に確認する。
詳細の観測窓と Onset Flux の尺度を A2 で固定し、30 ms など DRUM の値を根拠なく一般化しない。
既存 DRUM の定義は変更せず、2MIX の尺度変更で過去の DRUM Capture を読み替えない。
立ち上がりの丸まりや増減を観測しても、「パンチが良くなった」などの評価は出さない。

一度に動くのは一つの profile とし、別バイナリや二つ目の lease を追加しない。
切替時は旧 request、queue、history、固定対象を終了し、新しい定義世代で PRE と POST を揃える。
再起動やプロジェクト復元だけで未承認の解析を開始せず、前 profile の遅着データを採用しない。
2MIX が一条件でも未達なら 2MIX を有効にせず、DRUM の合否とは区別する。
共有 runtime や A 経路の退行は、両 profile に関わる blocker とする。

ATTACK の marker 表示は、既存の P95 50 ms／max 75 ms、worker P99 は hop 時間の25%以下、192 kHz二枠10分で drop 0 などの適用条件を再確認して維持する。
SPACE の 250 ms 以上を待つ特徴量とは、表示遅延の合格値を分ける。
SPACE の処理待ちを理由に ATTACK の表示を遅らせない。

### 4.4 SPACE への接続条件

最初の試作は、注釈済みのイベント位置を使う計算器の検証と、自動検出を含む検証を分離する。
前者が成功して後者が失敗した場合は、「数式は動くが自動観測の製品条件は未成立」と報告する。
打楽器主体のバス、疎な楽曲、持続音主体の楽曲、密な完成マスターを別々に集計し、DRUM の成績を 2MIX の成績へ合算しない。

2MIX で十分な観測が得られない場合の選択肢は、検出法の再設計、利用者が区間を指定する別の操作案、対象素材の限定である。
どの案を選ぶかは実験結果とともに Daisuke へ戻し、裏で DRUM へ切り替える fallback は作らない。
ATTACK 2MIX の event が確定しても、次の音まで 20 dB の減衰が観測できるとは限らない。
2MIX 用 ATTACK の製品 gate と、SPACE の区間採用 gate の両方を通って初めて自動接続を承認する。

## 5. PRE/POST の比較契約

差分には、同じ source 関係、定義 ID、チャンネル定義、sample rate、観測世代、対応が確認できた sample 座標を要求する。
DAW 時刻が同じだけで同じ内容と判断せず、既存の exact pairing と遅延情報の有効性を検証する。
遅延が不明、pair が変わった、片側が再起動した、seek をまたいだ場合は、成立していない差分を保持し続けない。
波形の見た目を合わせるための推測 shift や、欠測サンプルの補間は導入しない。

EARLY は共通のイベント起点と同じ二つの窓を両側に適用する。
ペア時の起点は選択した PRE event を一つの正本とし、確認済みの信号時刻写像で POST へ移す案を推奨する。
POST 単体は POST event を起点とするため、単体からペアへ移ると候補集合が変わり得ることを明示する。
POST にだけ生じた event、対応できない event、重なりのある event は別集計にし、成立ペアの分母から無言で消さない。
PRE 起点の採用は定義の承認事項であり、既存 ATTACK の一対一イベント対応や時間差の意味を変更するものではない。
双方が別々に検出した「近そうな onset」を、窓の一致を確かめずに引かない。
共通起点を相手へ渡す時点で必要なサンプルが失われないよう、通知遅延、保持時間、確定待ちを含めて試作する。
既存のイベント対応が、この 250 ms の計算に必要な取得条件まで満たすとは仮定しない。

DECAY のペア表示は、双方が成立する同じ連続した回帰区間へ揃える案を推奨する。
区間内の同じサンプル座標の包絡線点に同じ回帰規則を適用し、双方で観測幅などの条件を満たした場合に限り `D20_post - D20_pre` を表示する。
POST 単体で選んだ区間と、この共通区間が異なる場合は、ペア表示の PRE 値と POST 値も共通区間で再計算する。
この条件は採用率を下げる可能性があるため、単体の採用率とペアの採用率を別に実測する。

集計は成立したイベントごとに差分を計算してから行う。
PRE 全体の中央値と POST 全体の中央値を引かず、共通集合に属する差分の中央値と分布を示す。
表示の意味は「この区間の観測値の差」であり、「残響を追加した量」ではない。
EQ や compression だけでも包絡線が変わる条件を負例として残す。

## 6. 観測の寿命と欠測

常設 Meter Session と追加解析の観測期間は別物として扱う。
DECAY を表示している間だけ解析し、FIELD や非解析画面へ戻ると停止する案を推奨する。
別の optional analysis へ移るときは同じ lease を使い、同一 POST 内で二つの解析方式を同時に有効化しない。
editor を閉じると lease を解放し、再表示では新しい観測 run を開始する。
過去の解析結果は明示的な Capture として残せるが、非表示期間も計測していたかのような Session 統計には混ぜない。

| 状態 | 解析と表示の扱い |
| --- | --- |
| 取得待ち | 候補を集めている事実を示す。値をゼロで埋めない |
| 候補が未確定 | 完了前の値を公開しない。窓完了または棄却で遷移する |
| 有効な観測あり | 値、単位、採用数、最後の観測時刻を同じ snapshot から表示する |
| 無音または停止 | 現在の音に対応する描画を消す。過去の集計は「停止中の観測」と区別する |
| 明示的な固定 | 固定したイベントの図を保持し、ライブ値に見せない |
| PRE 不在または片側未成立 | 差分は未定義。POST 単体を見る操作は利用者が選ぶ |
| 解析枠不足 | 現行 coordinator の状態表現を使い、解析を起動しない |
| seek、定義変更、再起動 | 未完了候補を破棄して世代を変え、旧 run と接続しない |
| RESET | 既存の Meter Session reset を維持し、追加解析側の候補と集計も新世代にする |

一時的な GUI poll miss は、新しい「無音」や「失敗」の証拠にしない。
採用数だけを信頼度と呼ばず、観測期間、最後の更新からの経過、棄却理由を詳細表示できるようにする。
独立性がない同一イベントの再通知は採用数に加えない。
この run の最新 240 件を保持する場合は、その範囲を表示し、全曲や全 Session の分布と呼ばない。
候補数、採用数、棄却数、保留数、保持から外れた数の対象範囲を揃え、総数の収支をテストする。
単一 event の値は表示できても、分布や集計を出す最低件数は別に固定する。

## 7. 実装構造の案

計算器は GPL 側の純粋なモジュールとし、GUI、ホスト時刻、ファイル操作、Reference の試聴状態へ依存させない。
同じ計算器をライブ観測と検証済み Reference 音声の非 RT 解析で使い、二つの数式実装を作らない。
Kirin OS のプロプライエタリコードは取り込まない。

現行 `AnalysisViewMode` と画面遷移は DECAY を持たないため、既存 ATTACK を裏で二重起動する方法では接続しない。
DECAY route 内で onset 候補生成と減衰計算を順序付け、一つの optional owner の予算で完結する構成を G2 で定める。
TIME の ATTACK と SPACE の DECAY は別の公開結果を持ち、同時に別 lease を取得しない。
2MIX と DRUM の対応 profile、対象外素材、POST 単体時、pair 時の要求内容まで activation matrix に含める。

既存の `shouldCaptureBufferForMeasurement()` は、Record 外の無音を通常の sample push から外す。
SPACE の連続窓をこの経路だけへ接続すると、正当なゼロ sample と取得欠落を取り違える。
解析が有効な間のゼロ sample と低い tail を含む専用の bounded ingress、または等価な正確な区間供給を設計し、Watch の表示用 Inactive 判定と分離する。
host が callback を止めた時間をゼロ sample として補わず、その場合は中断または欠測にする。

| 責務 | 設計する境界 |
| --- | --- |
| 入力と区間選択 | 既存の有界 ingress を使い、方式の選択は単一 coordinator が所有する |
| EARLY の保留 | onset 確認時に残っている過去部分を取得し、未来部分は専用の積算状態で完了まで待つ |
| DECAY の計算 | 非正規化パワー、連続性、観測幅、回帰結果を同じ候補として確定する |
| ペア対応 | 共通起点と共通区間を運び、双方の成立後だけ差分を公開する |
| 集計 | 有界な候補集合、採用数、棄却数、観測期間を所有する |
| GUI 公開 | 完全な immutable snapshot を非ブロッキングで読み、計算中の内部状態へ触れない |
| 保存と Reference | source identity と定義 ID を検証し、正本 Record と別の表示用結果として扱う |

EARLY のために、既存 ATTACK の前 100 ms と後 30 ms の確定処理を遅らせない。
過去部分を回収できなければ欠測とし、250 ms のリングを単純に読み直すだけの設計にはしない。
ペア通知の保持余裕が足りない場合は、非 RT 側の専用保持を追加して費用を測る。
「追加メモリ 0」や「追加計算 0」を前提にしない。

初期の容量案は、包絡線 6 秒、完了候補 240 件、保留候補 16 件とする。
これは現在ある規模を出発点にする設計案であり、正しい容量であることは未確認である。
最大 sample rate、両チャンネル、PRE と POST、同時 2 オーナー、ペア待ちの保持を含む最大 bytes を算出し、製品実装前に固定する。
満杯時は新しい未完了候補を明示的に棄却して数を記録し、可変長に成長させたり欠けた候補を完成扱いにしたりしない。

回帰、自己相関、FFT、配列の確保、I/O は Audio Thread へ置かない。
通常の A 経路は 0 samples latency と bit identity を維持し、観測のための未来待ちは音声に遅延を加えず表示側だけで扱う。
新しい解析は optional worker の仕事とし、既存 Watch や Record の計測を待たせない。
既存の C ABI、wire enum、Record、TRACE、persisted PSB は読み替えず、表示専用の versioned contract を追加する。
ATTACK 2MIX と SPACE の入力保持を共有する場合も、公開される計算結果、定義 ID、確定期限、適用素材は別契約にする。

## 8. Reference への接続

最初に検証するのは、同じ定義の計算器を既知のファイルに適用し、ライブ経由の結果と一致させることである。
現在の Reference 詳細形式には DECAY や EARLY の項目がなく、未知のプロパティを拒否する実装である。
既存の粗い全曲 waveform から 80 ms のエネルギーを復元したり、schema v2 に未合意のキーを追加したりしない。

Kirin OS と統合する段階では、新しい測定 artifact の所有者、形式の version、読み書きの責任、旧版との互換動作を合意する。
接続は既存の Work を中心としたファイル契約を通し、Hypha が Work や Reference の正本を書き換える構造にはしない。
同じ GPL 計算器で行う Hypha 内の非 RT 解析を優先案とし、Kirin OS に測定ロジックを複製する案と混在させない。

結果には source のファイル／PCM identity、sample rate、チャンネル、cue 範囲、定義 ID、候補選択規則、観測範囲を結び付ける。
同名ファイルの差し替え、cue 変更、定義変更で古い値を再利用しない。
元ファイルの検証や解析が失敗した場合は該当比較を無効にし、通常の A 経路を維持する。
分析結果だけが欠ける場合は、既存契約で成立している original 試聴を妨げない。

同曲の対応区間では、対応の根拠がある範囲だけを比較する。
別曲間では候補分布を並べることはできるが、イベント差分や処理効果とは呼ばない。
定数ゲインに対する式の不変性と、異なる音色や編成間の比較可能性は別に検証する。
RUN／WORK／TARGET の到達項目を、測定値を追加しただけで達成扱いにしない。

SPACE のローカル観測は既存どおり OS 所有を要求しない。
Reference 連携には現在の entitlement と source 検証を適用し、追加値を取得することで権限を迂回しない。
Blind 中は新しい値、図、source 名、差分を UI、accessibility、Capture からも開示しない。
解析の開始や結果の到着を理由に、試聴を B へ自動切り替えしない。
Reference の ATTACK 比較にも profile と定義 ID の一致を要求し、DRUM の transient 値を 2MIX の尺度として表示しない。
Preset の view 指定に解析 profile を運ぶ必要がある場合は、既存形式の暗黙解釈ではなく契約差分として合意する。

## 9. 小型表示を先に成立させる

FIELD と DECAY は明示的な subview 切替にする。
現行 `HyphaObservationPageContract` は SPACE 全体を absolute 固定にしているため、domain 単位の判定を DECAY へ流用しない。
FIELD は現行の local absolute を保ち、DECAY だけに単体とペアの capabilities、help、hit target、Capture metadata を定義する。
描画だけを差分に変えて内部 target や accessibility を absolute のまま残さない。
大きな状態文字で本文を覆う方式や、表示に無関係な FOCUS 操作を残す方式は使わない。
必要な操作、値の出所、単位、観測時刻を専用の領域へ配置し、その後に図を入れる。

| サイズ | 最低限成立させる内容 |
| --- | --- |
| 300×200 | FIELD／DECAY の入口、選択した一指標、単位、採用数、取得中／停止中、観測の経過時間。EARLY と DECAY は明示切替 |
| 375×250 | 同じ情報を維持。観測数を削って数値だけにしない |
| 450×300 | 二指標、採用数、観測の経過時間。図より数値と状態を優先 |
| 600×400 | 二指標とペア内訳、選択区間の包絡線、観測点と回帰線の区別 |
| 900×600 | 採用分布、棄却理由、回帰区間と観測幅。未承認の指標は追加しない |

必要なラベルは現在の共通 font floor 11 logical px を下回らず、文字の横縮小を行わない。
11 px で読めることを自動的に合格とせず、Windows の 150% 表示と実際の読解で確認する。
収まらない場合は図と同時表示する項目を減らし、未検証のまま小型表示だけ機能を隠さない。
UI の文言は CE 2226 の既存規範に合わせ、良否、警告色、改善推奨を追加しない。

ライブ包絡線、回帰による線、固定した過去の図は視覚的に区別する。
EARLY は 250 ms の観測完了前に値を出さず、DECAY も必要な区間が確定するまで待つ。
この表示遅延を、音と瞬時に一致する図として説明しない。
Capture には採用した定義、対象、観測期間、値と欠測状態を同じ snapshot から残す。

## 10. 実験と合否の条件

実験素材は、計算器の正しさ、自動区間選択の成立、実際の比較用途を分けて評価する。
既知の指数減衰ノイズだけで成功しても、2MIX の残響推定が成立したとは扱わない。
Ratnam らの研究は最尤推定と統計処理を音声に適用した根拠であり、今回の回帰や 2MIX の精度保証ではない。[原論文](https://www.brl.uiuc.edu/Publications/2003/Ratnam-JASA-28772003.pdf)

| 検証対象 | 入力と確認事項 |
| --- | --- |
| EARLY の計算 | 同じ PCM と固定起点を直接積算した独立参照値、80／250 ms 境界、mono、同相、逆相、片側無音 |
| 減衰の計算 | 既知の傾き、複数 seed、二段減衰、T60 相当 0.3／0.5／1／2／4／8 秒を含む信号。採用できる区間とできない区間を分ける |
| 原因の取り違え | ドライな減衰、持続音、fade、gate、EQ、compressor release。ドライな減衰を強制的に gap にするのではなく、残響と断定しないことを確認 |
| 欠測と境界 | 無音、定常信号、ノイズ床、未完了窓、次 onset、停止、seek、loop、drop、満杯、重複、worker 再起動 |
| PRE/POST | 同一入力、固定ゲイン、既知の遅延、不明な遅延、片側だけの再起動、異なる定義、共通区間の採用率、イベントごとの差分からの集計 |
| Reference | 同じ PCM のライブ／非 RT 一致、別曲の非対応、cue 変更、ファイル不在、破損、差し替え、旧 schema、Blind と権限境界 |
| リアルタイム性 | 1／2 オーナー、3番目の待機、対応上限を含む sample rate、可変 block、長時間再生、復帰。A の bit identity、0 latency、drop、queue 最大使用量 |
| 描画と操作 | PRE／POST の全サイズ、自由リサイズ、DPI 100／150／200%、無音、固定、Capture、文字欠け、不要な hit target |

計算器の初期合格案は、十分なエネルギーがある固定窓の EARLY で独立参照との差 0.01 dB 以下、既知の直線に対する傾きで相対誤差 1e-6 以下とする。
これは数値実装の検査であり、雑音を含む素材に対する精度の宣言ではない。
固定起点でクリップや測定下限に触れない定数ゲイン試験では、EARLY と DECAY の不変性、および差分ゼロを確認する。
自動検出ではゲインによって候補集合が変わり得るため、候補数の変化まで隠して「完全に音量非依存」とは主張しない。

実素材の初期案は、開発用 12 抜粋と、別楽曲による未使用評価用 12 抜粋を用意することである。
打楽器主体、持続音主体、疎な編成、密な 2MIX を両群に含め、利用可能な権利を確認する。
同じ曲の別区間を独立した holdout 曲数として数えず、曲ごとの偏りを報告する。
この規模は探索開始用であり、市場全体への適用を保証する標本数ではない。

SPACE の自動区間選択の採否基準案は、独立に注釈した適格区間に対する採用 precision 95%以上、coverage 70%以上とする。
「適格」は残響の有無ではなく、採用定義の連続性、観測幅、測定下限を満たす区間を指す。
区間の対応許容幅、境界の判定、曲単位の集計方法も未使用評価の前に固定する。
この数値は研究を進めるか判断するための提案であり、検証済みの性能ではない。
ペアの coverage は単体と別に測り、差分が実用になる最低値も開発用素材の段階で承認してから固定する。
この SPACE 用の素材数と採用基準で、§4.3 の ATTACK 2MIX 専用 gate を置き換えない。
ATTACK の未使用評価音声や注釈を SPACE の開発で開いてしまうことも避け、用途別に隔離する。

雑音を含む減衰では誤差の中央値、P95、採用率を併記する。
最小候補数や適合度の閾値を、未使用評価の結果を見ながら調整して合格にしない。
変更が必要なら定義 ID を更新し、未使用素材を用意し直す。
観測数 N を増やすだけで「部屋鳴り」や「奥行き」の正しさを保証したことにはしない。

製品ゲートには既存の Rust test、Clippy、FFI ignored parity と pairing、出荷ソースゲート、native UI、実際の VST3 音声検証を含める。
既存の UI 描画時間上限は緩めず、1 オーナーと 2 オーナーの両方で変化中の状態を測る。
新しい解析費用は最大 bytes、worker の処理時間分布、drop、queue 使用量、表示更新時間を別々に記録する。
CPU 使用率の平均だけで、待ち時間や瞬間的な滞留を見落とさない。

## 11. 着手順序と成果物

作業は次の依存順で進める案とする。
順序を分けるのは、検証前の定義を製品へ固定しないためであり、同じ UI へ局所修正を積み重ねる実装手順ではない。
G1 以降は機能ごとに適用し、ATTACK 2MIX、SPACE、Reference 拡張の未完了条件を一つの承認待ちに束ねない。
例えば EARLY／DECAY 用 Reference 形式の未合意は、その拡張の blocker であり、通常の ATTACK 2MIX の独立した公開を止める条件にはしない。
共有 runtime、音声、既存 Reference の退行は、影響する全機能の blocker とする。

| --- | --- | --- |

数式の検証が成功しても、自動選択、ペア比較、性能のどれかが不成立なら、対象の新規計測機能を G3 へ進めない。
その場合は失敗した条件と選択肢を Daisuke に示し、対象限定や別操作への変更を承認なしに行わない。

未検証の測定意味を後のレビューで調整する前提では実装に入らない。

| ATTACK と入力保持 | `attack_runtime*`、`attack_detail`、`HyphaAttack*`。DRUM／2MIX の独立定義、共通 runtime、再利用できる保持を分離 |

| ペアと transport | 既存 ATTACK の対応、専用 payload、世代と保持期限、Windows transport の version 境界 |
| ABI と JUCE bridge | `kirin_hypha_ffi` の表示専用追加 ABI、`PluginProcessorAnalysis`、`PluginEditorAnalysis` |
| 操作と表示 | `HyphaObservationPageContract`、Observatory の layout／state／capture、SPACE subview と専用 painter |
| Reference | `ReferenceRuntimeV2Measurement*` と source／cue／権限／Blind。Kirin OS と合意した追加契約に限定 |
| 製品文書と検証 | product contract、invariants、対応する Rust／FFI／native UI／Windows の回帰テスト |

現行文書には旧表示仕様が残る箇所があるため、実装前に B-705 のコードと差分を照合する。
既存文書を本提案だけで上書きせず、承認した意味と対応テストを揃えて改訂する。
Reference の形式変更は Hypha 単独で確定できないため、次の契約調整が必要になる。

**Handoff 案**

- To: Kirin OS Reference 契約担当
- From: Codex 2026-09-06
- What: EARLY／DECAY の測定 artifact の所有者、version、source／cue identity、旧版互換、欠測時の扱いを合意したい。
- Why: 現在の Reference 詳細 schema は閉じた形式で、新しい二指標をそのまま追加できないため。
- Next: G1 の定義候補と必要メタデータを確認し、既存の原音試聴と Blind を壊さない契約差分を返す。
- Ref: 本書 §8、`docs/reference_runtime_v2_handoff_20260905.md`、`ReferenceRuntimeV2Measurement.cpp`。

この Handoff は計画上の依頼案であり、別タスクの作成や外部への送信は行っていない。

## 13. 今回承認を提案する範囲

最初に承認を求める単位は、A0 の表示／入口設計と、G1 の二系統の研究までとする。
ATTACK 2MIX は独立した製品開発として計画に含め、SPACE の試作の付録にはしない。
EARLY と DECAY の定義、同じ区間での PRE/POST 比較、DRUM と 2MIX の適用範囲を、製品の計測経路を変更せずに確かめる。
その成果物は、DRUM の表示仕様、2MIX の評価契約と候補、SPACE の実行可能な試作、入力と期待値の台帳、各合否レポートとする。

G1 に向けた推奨判断は、DRUM と 2MIX を明示して区別すること、2MIX 用 ATTACK を独立に作ること、SPACE は広帯域の二指標を優先することである。
DECAY は 20 dB 相当時間を主値候補にし、DEPTH を奥行きとして出さない案を採否判断へ含める。
Reference、REPEAT、帯域別の研究順序は、この結果を見て承認する。
工数と公開日は、自動選択とペア保持の難易度が判明する前には確約しない。
素材の使用権、未使用評価の隔離履歴、二人の注釈者、Reference 契約の担当者、両 OS の検証時間を着手時の依存関係として確認する。
Windows は現在の操作停止が解除され、他の実装との占有調整が済むまで操作しない。

## 14. 再点検で追加した実装前の必須成果物

本書は研究と採否判断の計画であり、回帰閾値などが未決定のまま使える実装仕様ではない。
次の成果物を揃えて G2 を完了し、その版の hash とテストを実装着手時に固定する。

| 要求 ID | 凍結する成果物 | 検証の最低条件 |
| --- | --- | --- |
| SA-01 | DRUM、2MIX、SPACE の文脈と activation matrix | PRE/POST、全 domain、全サイズ、profile 切替、pair 有無で意味と操作が一致 |
| SA-02 | sample 丸め、パワー定義、EARLY 重なり分類、DECAY 区間選択を含む実行可能な定義表 | block 分割不変、固定起点の独立参照値、正当な無音と drop の区別 |
| SA-03 | PRE 起点、遅延根拠、共通区間、片側成立、欠測の pairing 契約 | identity、未知遅延、時刻変更、遅着、重複、片側再起動で偽の Δ を出さない |
| SA-04 | 取得、保留、確定、棄却、固定、停止、復帰の状態表 | finite な deadline と容量、候補数の収支、停止後に live 図を残さない |
| SA-05 | 素材別の評価器と開発用／holdout の隔離台帳 | ATTACK と SPACE の別 gate、注釈者間一致、棄却と coverage、未知曲での検証 |
| SA-06 | wire / ABI / Capture / Reference の version と capability 表 | 新 POST と旧 PRE、旧 POST と新 PRE、旧 Capture、不明定義を読み違えない |
| SA-07 | 最大 bytes、worker P99、描画時間、全対象ファイルとテストの対応表 | 2 owner と待機、最大対応 SR、低負荷時と競合時、両 OS の同一 commit 検証 |

通常計測は既存の互換範囲内で旧版の相手とも維持し、新しい capability が確認できない相手へ新解析を要求しない。
旧 Capture は元の定義で読むか、未対応という事実を表示し、新定義で再解釈しない。
enum 値の再利用、未初期化の追加 ABI field、payload 長の推測を禁止条件にする。

G2 の各未決定値は、決定担当、必要な実験、期限ではなく次に進む条件を持つ台帳へまとめる。
公開 precision や coverage だけでなく、誤差が許容できる母集団と、利用者が読む有効桁も承認する。
数値が未確定なら該当機能の製品実装を開始せず、別機能を巻き込まず研究結果へ戻る。
最新版への案内は測定の source や解析枠を使わない共通 shell 機能とし、両計画の共通再点検文書に分離する。
