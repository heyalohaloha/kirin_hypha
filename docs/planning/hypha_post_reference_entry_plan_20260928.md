## 1. 採用する三点

1. **POST一つで始める。** ステレオのmix/master busの処理列の最後にPOSTを置き、LEVELで自分の音を観測する。処理前後の差を知りたくなった時にPREを加える。
2. **実際の曲を比較相手にする。** Kirin OSで管理したVersionやCatalogの参照曲を、既存のReferenceから選んで聴く。判断は利用者が行う。
3. **既存画面と操作を使う。** LEVEL、Reference、Catalog、既存Blindをつなぐ。通常比較で最初の成功を作り、Blindは本人が必要とする場合に進む。

無料のPOST単体計測だけでも利用が完結する。ReferenceにはKirin OSの権利と参照の準備が必要であることを入口で示す。OS未導入を計測の失敗や不足と扱わない。

対象はステレオ2MIXの導入経路。既存のTRACK / STEM、PRE/POST計測、ローカルPRE/POST Blindの入口と機能は維持する。製品全体をマスタリング専用へ変更しない。

## 2. 今回の採用に含めないもの

- EBU Mode、配信先別LUFSターゲット、合格帯、順位・近さ・品質スコアの新設。
- 既存のCheck Preset、曲名、Version名、利用者ラベルの削除・強制的な非表示。
- 音源準備・位置検証・Gain Match・音声出力の責務移動、独立プレーヤー、新しい比較エンジン。
- 別曲へ同曲の位置合わせやVersion Blindを適用すること。
- LEVELの測定項目、既存のTP・Clip事実表示、解析方式の変更。
- 全員へのReference必須化、起動時の自動試聴、保存済み画面やサイズの強制上書き。
- 15秒で初回登録から比較まで完了するという保証。

「規格目標プリセットを追加しない」と「参照の組合せを保存する既存Check Presetをなくす」を混同しない。放送等の規格適合を調べる作業は、この入口の成果として約束しない。

## 3. 利用者の操作

### 3.1 POSTだけで計測する

1. ステレオmix/master busの処理列の最後にPOSTを置く。
2. Meter Contextは本人が2MIXを選び、LEVELを開く。挿入場所から自動推定しない。
3. DAWで再生し、POST入力の絶対値を読む。PRE未接続を必須設定の未完了と見せない。
4. 自分の処理前後を確認したい時にPREを追加し、POSTでそのPREを明示選択する。

新規利用の説明と実演はコンパクトLEVELから始める。コンパクトで同時表示できる項目は現行契約に従い、大画面の全項目を詰め込まない。起動既定の変更は前提にせず、まず現行初期状態と保存復元を確認する。

### 3.2 参照を聴く

比較対象によって次の二経路を案内する。

| 目的 | OSでの準備とHyphaでの選択 | 最初の成功 |
| --- | --- | --- |
| 同じ曲の別Versionと比べる | OSの登録済みVersionをBで選択。DAWのライブAとの同曲・位置・固定ゲインの検証を待つ | 明示的にA/Bを聴き、Aへ復帰する |
| 別曲で低域や広がり等を確かめる | OSの既存Reference設定でCatalog音源をCheckに割り当てて保存し、HyphaのCで選択 | そのCheckのCue・再生条件でA/Cを聴き、Aへ復帰する |

別曲CにBの同曲時間対応を流用しない。Cの音量条件は選んだCheckの現行規則を説明し、「全参照が自動的に同じ位置・同じ音量になる」と一括表示しない。

登録済みの参照がある場合はHypha内の選択から始める。毎回OSで再登録・再接続させない。未登録時だけOSの既存設定画面で準備する。

### 3.3 必要ならBlindへ進む

同曲Bとの通常比較が成立した後、本人が希望する場合に既存Version Blindを開く。既存の画面拡大、必要なGain承認、試聴、回答、Reveal、終了・復帰を維持する。

Check Cの案内からVersion Blindへ誘導しない。ローカルPRE/POST BlindはPREを追加した処理前後比較の経路に残す。BlindはPreference Listening Trialであり、音質改善やABX識別の証明と説明しない。

## 4. 表示で守ること

- 通常比較では、聴いている音源と表示数値の対象を区別できるようにする。Aの計測を続けながらB/Cを聴く場合、既存表示で伝わるかを先に確認し、不足する箇所だけ短い事実表示を補う。
- 表示は実出力の確認に従う。Bを要求しただけで「Bを再生中」と表示しない。準備待ちやAへ戻った状態も区別する。
- Blind中は既存の秘匿を優先し、波形、数値、色、tooltip、accessibilityから割当を漏らさない。通常比較用の音源表示をBlindへ持ち込まない。
- 音源は曲名と版を識別できる表記にする。同名別Version、長い名前、日本語名でも取り違えない。利用者自身の納品先ラベルは保持する。
- 準備不足は既存Guideにその時の次の操作を表示する。明示操作の失敗は通知し、内部再試行を通知列にしない。
- 利用者が選んだ参照を、製品の推奨曲、目標値、合否へ読み替えない。

## 7. 受入条件

| 場面 | 合格条件 |
| --- | --- |
| POST単体・OSなし・PREなし | ステレオ2MIXの絶対計測ができる。参照登録や購入を要求せず、通常Aはbit identical、追加latency 0 samples |
| 同曲B | 版を選び、検証成立後に明示試聴し、実出力のA復帰を確認できる。校正不足をMATCHEDと表示しない |
| 別曲C | Catalogから意図した曲・版・Cueを選んで保存し、POSTで聴ける。B用の同曲一致やBlind成立を要求しない |
| 名前と複数POST | 同名別Versionを識別でき、他POSTの選択が変わらない |
| 試聴と計測 | B/Cを聴いても正本A測定・Recordは変わらず、通常画面で数値の対象を説明できる |
| Blind | 任意で開始し、秘匿・回答・Reveal・復帰が現行契約どおり成立する。ローカルPRE/POST Blindとの排他も維持 |
| 欠損・変更・曖昧位置 | 音源欠損、identity変更、位置不成立では比較を開始せず、Aを維持し、本人の操作に対応する案内を出す |
| OS不在・再起動 | 有効なLibraryをlease切れだけで破棄しない。権利・音源・比較根拠は既存契約どおり検証し、復旧だけでB/Cへ切り替えない |
| 形式の境界 | 検証と必要な承認を経たSRCは既存どおり扱う。非対応layoutを拒否し、5.1ではReferenceを有効にしない |
| 保存・復元・offline | DAW再openで通常Aから開始。offlineの最初のbufferから比較音や比較gainを混入しない。リアルタイム書き出し前の明示A復帰手順を保持 |
| サイズ・英日表示 | 現行の対応サイズと両言語で選択・対象表示・次の操作が読める。Blind秘匿はaccessibilityも確認 |
| 初見と再利用 | POST単体、B、Cの各課題を手順の口頭補助なしで完了し、聴いた対象・測定対象・A復帰を本人が説明できる |

動線検証は初回準備と登録済み再利用を別に計測する。操作回数、アプリ切替、準備待ち、誤選択、説明介入、復帰までを記録し、既存動線と比べる。15秒は保証や合否値にしない。参加者と環境を記録し、少数の成功を一般化しない。

実装時は対象native/UI試験、source契約、行数規約、`cargo test --workspace`と`cargo clippy`を実行する。FFIを変更した場合はAGENTS.md指定のignored parity/pairing_candidatesも一覧件数を実測して全件実行する。今回は計画文書のみのため製品テストは実行しない。

実機受入は公開対象のmacOS AU/VST3とWindows VST3を同一最終候補に結び付ける。AAXは対応する実機証跡を別に扱い、既存のPDC未確認を本導線の成功で解消済みにしない。Windows機を操作する際は共通Runbookを先に読む。
