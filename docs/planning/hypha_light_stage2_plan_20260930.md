## 3. 第2段階の目標（完成の定義）

1. 各ページに主役の窓が一つあり、VUの枠と同じ素材（ブロンズの面取り）で立って見える。
2. 光は一つの光源から来る。
   - 光の着地点は、主役の窓の上辺のうち光源に最も近い点。
   - 明るさは光源からの距離で減る。二つの窓が同じ形に光ることは無い。
   - 光源から来ない光（どの窓にも同じ位置に置く光の点など）を置かない。
3. 脇役（card、panel、DRUMのlane、操作部）は第1段階のまま静か。
4. VUと並べて違和感が無い（光源の向き、素材の色が揃っている）。
5. 5つの大きさ（100%〜300%）と拡大表示（450%など）、日英、Mac／Windowsで同じ見え方。
6. 軽さは第1段階と同じ。枠と光は静的な素材として描画cacheに一度だけ描き、フレームごとの描画量を増やさない。

## 4. 光のモデル（見本で使った値。D1・D5で決定）

- **光源**：editorに一つ。位置はeditorの寸法に対する比率で決める。
  - 見本：横0.42W、縦−0.6H（editorの上方、やや左）。
  - 300%を超える拡大表示は900×600の配置を拡大するだけなので、同じ比率で光も拡大される。
- **着地点**：主役の窓の外枠の上辺で、光源のx座標に最も近い点（光源が窓の外なら窓の端）。
- **明るさ k**：着地点から光源までの距離 d を、editorの対角線 diag で割って決める。
  - 見本：k = clamp(1.3 − d / diag, 0.35, 1.0)。
- **枠の構成**（外側から順に）：
  1. 柔らかい落ち影（4段）：枠が筐体から少し浮いて見える。
  2. 暗いブロンズの面取り（上から下へ暗くなる）。
  3. 着地点を中心にした放射状の光（面取りの上だけ、k倍）。
  4. 外周の黒い線。
  5. 内側の縁の金色の細線（着地点でいちばん明るく、離れるほど暗い）。
  6. ガラスの床の暖色の照り返し（着地点の真下がいちばん明るい）。
  7. ガラス上端の影（ガラスが枠より奥にあることを示す）。
- **角**：窓の四角い角は筐体の色で埋め、丸い枠だけを見せる。
- **寸法**（見本）：幅900のとき、枠の太さ7 px、角の半径14 px。editorの幅に比例。
- **座標**：各ページの部品は自分の座標で描いている。editor座標での光源の位置を各部品へ渡す仕組みを作る（例：部品のeditor内での位置を、presentation contextと同じ経路で渡す）。

## 6. 小さい大きさの扱い（D4で決定）

見本の寸法を100%（300×200）へ比例させると、枠の太さ2.3 px、角の半径4.7 pxになる。面取りとして読めない恐れがある。

- **案A**：枠の太さに下限（例：3 px）を設け、全サイズで同じ構成にする。
- **案B**：125%以下は、細い縁と着地点の光だけに簡略化する。
- **案C**：125%以下は主役を置かず、第1段階のまま静かにする。

100%のLEVEL（値の枠が3つだけ）のように主役の候補が無い画面も、ここで決める。

## 7. 実装の方針

- **全ページを一括で**：禁止事項2「1画面だけ修正して他を放置するな」に従う。見本は全ページ×5サイズで作り、承認後に全ページを1回の変更で実装する。ページ単位の小出しはしない。
- **1か所に集める**：光源と枠の描画は新しい1ファイル（500行以下）に置く。各ページは「主役の窓の矩形」と「editor内での位置」を渡すだけにする。第1段階の`paintMainEdge`はこの枠に置き換える。
- **cache**：枠はページの構造画像（chrome cache）に入れる。cacheの鍵に「editor内での位置」を加える（位置が変われば光も変わるため）。
- **画像か描画か（D2）**：
  - 見本はベクター描画（寸法に追従しやすい）。
  - VUと同じく画像の枠を9分割で伸縮する方法もある。VUとの質感の一致は画像の方が近い。一方で、窓の縦横比がページごとに大きく違うため、角と辺の伸び方の検証が要る。
- **VU**：画像は変えない。VUの画像の光の向き（上方）と、第2段階の光源の向きが合っているかを確かめる。
- **文書**：visual system §3.2を改訂する。不変条件を1行追加する（光源はeditorに一つ、主役の窓だけが枠と光を持つ、同じ形の光を複数の窓に置かない、映り込みの形を置かない）。

## 12. リスク

- **金色の輪が飾りに見える**：着地点を一つにし、周回で暗くなる規則を守る。複数の窓に同じ光を置かない。

- **性能**：放射状の光はcacheに一度だけ描く。フレーム予算で確かめる。
- **Windows**：グラデーションの描画がMacと違う場合がある。実機で確かめる。
- **世界観**：ブロンズはVUの筐体で既に使っている素材で、Hyphaの世界（CE 2226の地下の観測設備）の範囲内。新しい色は増やさない。

### 14.2 実装

- `HyphaKeyLight.h`：光源一つ。各部品は、editorの論理座標の根（`scaleRoot`）までの位置から光源の位置を求める。描画中の部品は`key_light::Scope`で光を下の描画へ渡す。
- `HyphaMainFrame.h`：主役の窓の枠。落ち影2段、暗いブロンズの面取り、着地点を中心にした光、外周の黒い線、金色の内側の縁、下の縁の照り返し、ガラス上端の影。cacheの鍵に着地点と強さを含める。
- 主役の窓：FREQ、TIME HISTORY／RUN、SHARP、LIVE、DRUMのHISTORYの行（帯域の面、読み、小さい数直線を含む）、SPACEの密度、REFの比較の窓、LEVELの履歴（無い大きさでは値の枠のまとまり）。
- 第1段階の窓の内側の光（`paintMainEdge`、DRUMの`mainEdge`）は取り除いた。光は枠だけが受ける。
- 第3段階：操作部の板（ページのボタン、帯域のチップ、REFのボタンと選択欄など）の上の縁は、光源に最も近い位置で最も明るい。光のscopeの外で描く板は、従来どおり左端が明るい。
- 第4段階：Blind、Guide、通知、MENUは主役の窓を持たない面として静かなまま。板の光は同じ規則に従う。
- 第5段階：450%などの拡大表示は900×600の配置ごと拡大するので、枠と光も同じ比率で拡大する。実画面での確認はDAWで行う。

### 14.3 検証

- `verifyMaterialLight`：cardは静か。主役の窓は枠の中にあり、光源の左の窓は右端、右の窓は左端に光が当たる。ガラスの中は光らず、映り込みが無い。板の光も同じ位置に当たる。
- `verifyCachedMaterialLooksPainted`：枠と板をcacheから貼っても、直接描いた場合との差が3階調以内。
- `verifyMenuArrowContract`：比較用の板を同じ場所に置き、同じ光の下で比べる。
- 描画予算：LIVEとSHARPの描画時間（cacheなし）が上限内（2026-10-01、Intel Mac：LIVE 900×600で7.4 ms、SHARP 8.7 ms）。
- 目視：全ページ×5サイズ（`KIRIN_HYPHA_LIGHTING_REVIEW_DIR`）、REF、DRUMの帯域表示。
- 未実施：Studio One／Pro ToolsとWindows検証機での実物の確認。
