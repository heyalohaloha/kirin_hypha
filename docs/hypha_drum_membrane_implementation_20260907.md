# DRUMの上下分離と半透明膜の実装

## 実装と未完了の境界

2026-09-06の指示を受け、上部を音の輪郭、大きさ、時間軸に集中させ、下部へ打音の性質を集約した。
下部は扇から、厚みの偏りと細かな折れを持つ半透明の膜へ変更した。
これはB-730の検証候補であり、配布版への配置や公開は行っていない。

WindowsとmacOSの表示機能テストは合格した。
Windowsの描画性能は120条件を二巡して合格したが、macOSは一巡目が合格、再測定が119条件合格、1条件不合格だった。
**macOSの性能安定性と、DAW上の実音同期は未完了である。**
この記録の画像は合成データをJUCEコンポーネントで描いたもので、DAWの実音再生画面ではない。

## 上部は実測の時間軸を受け持つ

上部の描画関数には10 ms RMS包絡、表示範囲、サンプル時刻、サンプルレートだけを渡す。
下部のイベント詳細を引数から外したため、Sharpnessなどを変えても上部の輪郭や色は変わらない。
固定幅の小さな扇を履歴へ並べる処理も削除した。
その幅を発音時間と誤認させないためである。

| 表現 | 意味 |
| --- | --- |
| 横位置と横幅 | 実測サンプル時刻上の位置と継続範囲。左が6秒前、右が現在 |
| 輪郭の高さ | 10 ms RMSの大きさ。−72から0 dBFSまでの固定尺度 |
| 青い塗りと輪郭 | POST単体、または二段表示の各入力の絶対包絡 |
| 重ね表示の薄い無彩色の線 | PREの絶対包絡。POSTとの差分値そのものではない |
| 空白 | 無音域、欠測、無効値、異なる世代やチャンネル数の境界 |

上下対称の図形はRMS包絡であり、生波形の正負や位相を表さない。
右端の選択点、履歴の選択操作、イベント数表示は残した。
上部の補足表示とPRE/POSTラベルは最低11 logical pxへ揃えた。
小さい枠では既存の省スペース表示に従い、上部を省いて下部の数値を優先する。

表示時刻の補間は100 msごとに加減速する方式から線形へ変更した。
10 Hzの観測受け渡しと100 msの補間区間自体は残しており、音と画面の遅延をゼロにした変更ではない。
元の10 ms測定値、Record、IPCの周期は変えない。

## 下部は打音の性質を受け持つ

下部には選択したイベントの四量と、非対称に折り重なる4枚の膜を置く。
ここで扱うのは測定上の性質であり、音の良し悪しの採点ではない。

| 観測量 | 膜への対応 | 維持する測定上の意味 |
| --- | --- | --- |
| STRENGTH | 中央付近に偏った厚み、goldの光 | 30 ms attack RMS |
| BRIGHTNESS | 上下の開き、ice blueの光 | 100 ms Sharpness、acum |
| TEXTURE | 内部の細かな折れと皺、copperの光 | edge、Crest、plateauによる既存の複合量 |
| TRANSIENT | 右へ伸びる先端、tealの光 | 直前との局所contrast。横幅は秒数ではない |

左の `REAR` と右の `FRONT >` は空間的な向きであり、PREとPOSTの左右配置ではない。
色相、特徴量の算出式、固定の発光閾値、有効桁は維持した。
各形状パラメーターを個別に変えると、担当する厚み、開き、皺、前方到達点が変わる。
最終的な膜の輪郭にはこれらが組み合わさるため、四量の形が完全に独立した四つの図形になるわけではない。

PREは薄い無彩色、POSTは既存の固有色で、共通の絶対尺度を使う。
数値の差分は `POST−PRE` のままとし、PREがない場合はPOSTの絶対量を表示する。
未知の値を別の有効成分の色で補う処理は加えない。

動きには既存のRMS包絡から得る7つの曲率を使う。
独立した発振器、粒子、物理シミュレーションは追加しない。
PAIRではPREとPOSTへ同じ曲率を適用し、装飾だけで差分が生じることを避ける。
停止や無音ではLIVEの描画領域を黒へ戻し、明示的にLOCKした過去イベントは保持する。

## 描画負荷を抑える変更

上部の重複した流線と履歴標本を削除し、包絡の塗りと上下輪郭へまとめた。
包絡の頂点整理は最大0.05物理px以内とし、局所的な極値と欠測境界を保持する。
正本の600点の包絡は削減しない。
2^53を超える時刻でも精度を落とさないよう、相対サンプル数を整数で求めてから座標へ変換する。
同じ処理を下部のRMS補間にも適用した。

下部は1入力につき最大21個の塗りに制限し、連続グラデーションと細い縁を保った。
履歴用の512件キャッシュを廃止し、選択中の膜1件だけを保持する。
四量は丸めず完全一致で比較し、曲率だけは制御点とグラデーション位置の移動が0.05物理px以内の場合に再利用する。
一つのコンポーネントのキャッシュは画像pixel payload最大8 MiB、2枠では16 MiBである。
画像管理用メモリや一時的な描画データはこの上限に含めない。

上部をCoreGraphicsへ直接描くと、高DPIの包絡が負荷の中心となった。
macOSではJUCEのsoftware rasterへ一度描き、その画像を合成する。
一時画像は最大8 MiBに制限し、範囲外では同じvector描画へ戻す。
Windowsは既存の描画先へ直接描く。
Windowsにも中間画像を入れる試作では最大表示2枠が約17.5 ms以上となったため、その追加コピーを外した。

キャッシュとmacOSの中間画像は物理ピクセルに合わせて作り、端の切り上げ分を図形全体へ縮めて混ぜない。
画像の合成時は再サンプリングを省き、作成時のアンチエイリアスとグラデーションを使う。
小さな画像を引き伸ばして負荷を下げる方式ではない。

変更はGUI内に限定した。
Audio Thread、計測worker、通常の音声経路、Blind、PSB、SPACE解析はこの変更に含まない。

## 検証条件と結果

専用のconsole executableへ実際の表示クラスを組み込み、RelWithDebInfoで検査した。
JUCEは既存のローカル修正を含む7.0.12である。
製品用の埋め込みfontではなくinstalled/fallback fontを使うため、配布binaryの文字配置は別途確認が必要となる。

| 表示サイズ | 製品の5種類。描画領域292×74から872×382まで |
| DPI倍率 | 1、1.25、2 |
| PRE/POST表示 | 二段と重ね表示 |

| 予算 | 5回の更新中央値が1枠12 ms、2枠16 ms以下。最大24 ms、初回80 ms以下 |

2枠は独立したオブジェクトを同じoffscreen画像へ順番に描く検査であり、DAWの2ウィンドウを実際に開いた検査ではない。
測定時間にはsnapshotの反映と描画を含み、音声処理は含まない。

macOSの不合格は872×382、DPI 2、240イベント、2枠の重ね表示である。
再測定後の読み取りでは複数のnodeプロセスに高いCPU使用率があり、黒い非動作表示の診断値も約1 msから約2.25 msへ増えていた。
ただし測定中の負荷を連続記録していないため、不合格をすべて他プロセスのせいとは断定できない。
合格回だけを選ばず、再測定の不合格を残す。
完全な480条件分の記録は [性能データ](hypha_drum_membrane_frame_evidence_20260907.json) に収めた。
この測定後にTEXTUREの複合入力へ非有限値の拒否を追加し、表示機能テストを再実行した。
性能fixtureの入力はすべて有限値であり、描画方式は変えていない。

表示機能テストでは、上下の情報分離、既知の時間位置とRMS高さ、ピーク保持、欠測、NaN、無音、停止、LOCK、再起動相当の世代変更を確認した。
キャッシュと直接描画の差はDPI 1、1.25、2、4の奇数寸法で、alphaを含む加重色差の総量5%以内を検査した。
描画先のopacity、画像の余白、無効なDPI、8 MiB上限、vector fallbackも検査対象である。
四量は個別21段階と端点16通りを確認し、符号付き比較とPOST単体の既存試験を維持した。

`cargo test --workspace` は1843件PASS、37件ignore、終了コード0だった。

vendorにはbaseviewの既知警告127件とnih_plugの3件が残る。
変更したC++の最終ビルドに警告はない。

新規および変更したowned sourceは500行以下である。
リポジトリ全体の行数検査は、別作業中のReference関連6ファイルが500行を超えてFAILとなった。
