対象は Downloads の [hypha_space_decay_design.md](/Users/nishiodaisuke/Downloads/hypha_space_decay_design.md)（2026-09-04、B-687 / `119a63e` を参照）。
元文書の SHA-256 は `c3fe3def4075ad13b4d6608ee347477e8a8e262f2c017c4cbb5e2fa4728eb9da`。
現行コード（B-705 / `6389733`）、指定された旧コミット、一次論文、提案式の数値計算を照合した。
これは設計レビューであり、SPACE の新機能は実装していない。

## 採用判断

音の消え方を比較する機能には検討の価値があるが、この文書をそのまま実装指示書にはできない。
「既存の解析を無償で流用できる」という実装前提と、「包絡線の違いから残響量や奥行きを断定できる」という計測の意味に、それぞれ修正が必要である。

| 提案指標 | 現時点で支持できる意味 | 判断 |
| --- | --- | --- |
| EARLY | 同一イベント内の 0–80 ms と 80–250 ms のエネルギー比 | 定義を限定した試作候補。直接音／残響比とは呼ばない。 |
| DECAY | 条件を満たす区間の包絡線減衰率、または明示した外挿時間 | 試作候補。楽器の減衰と残響の識別能力は別途検証する。 |
| DEPTH | 採用イベント群における EARLY の IQR | 「奥行き」としては採用しない。分布のばらつきという事実なら再検討できる。 |
| REPEAT | 包絡線に含まれる反復周期の候補 | ディレイ検出とは区別する。BPM 一致だけで候補を除外しない。 |

RT60 準拠を主張しないこと、観測不足をゼロで埋めないこと、Audio Thread に解析を置かないこと、原音を変更しないことは維持する。
特に §5.1 の「残響と楽器の減衰を分離できない」という留保は適切だが、§6 と §7 の残響量、奥行き、処理効果の断定には、その留保が反映されていない。
以下は採用条件の提案であり、未実装機能を承認なしに後工程へ送る決定ではない。

## 1. 解析枠とデータの寿命

提案書 §4.1 の「2 枠は attack と spectrum が占有している」は、コードの意味と異なる。
2 枠は同時に動ける解析オーナーの上限であり、解析方式に一つずつ割り当てられているわけではない。
一つの POST 内では ATTACK と SPECTRUM は排他的に動作し、SHARP と LIVE も同じ仕組みを使う。
この排他制御は提案書の基準コミット `119a63e` にも存在したため、単に文書が古いことによる差ではない。

根拠は `analysis_lease.rs` の `ANALYSIS_SLOT_COUNT` と `spectrum_exchange_control.rs` の `set_post_analysis_mode` / `set_active_runtime_enabled`。
後者は一方の runtime を有効にすると、他方を無効にする。
現行 SPACE は共通メーターの表示であり、画面を開くだけでは提案の両入力が常時供給されない。
オーナーを増やさない設計は可能でも、解析方式の選択、開始／終了、欠測、計算量の契約は新たに必要になる。

同様に、履歴が存在することと、Meter Session 全体の候補を蓄積済みであることは異なる。
直近 240 イベントに EARLY の計算結果は保存されておらず、候補分布、採用数、棄却理由、世代、時刻の追加状態が要る。
「追加メモリ 0」「新規 FFT 0」は実測前の確定条件にはできない。

## 2. EARLY の 250 ms 窓

提案書 §6.1 の窓は、onset の時点ではまだ存在しない未来の 250 ms を含む。
既存の `AttackDetailTracker` は過去 250 ms のリングを持ち、onset 後 30 ms の特徴量と対応する Sharpness の準備ができた時点で詳細を確定する。
画面を開いた時に過去 240 件の EARLY を復元できる構造ではない。

新しい特徴量は、少なくとも onset 後 250 ms まで保留してから確定する必要がある。
ただし、ちょうど 250 ms のリングは、処理がブロック単位で先に進むと onset 側が押し出される余裕を持たない。
イベント別にエネルギーを逐次積算するか、遅延を見込んだ保持と専用の確定処理を設計する必要がある。
既存 ATTACK の前 100 ms と後 30 ms を壊さず、同時イベント数、停止直前、未完窓、次 onset の混入も定義する。
根拠は `attack_detail.rs` の `RETENTION_MICROS`、`capture_next_ready`、`capture_internal`。

EARLY の式自体は有限窓のエネルギー比として成立するが、初期窓にも残響が入り、後期窓にも楽器の持続音や次の音が入る。
したがって「EARLY は残響量」「直接音と残響の比」は、この式だけからは導けない。
一定パワーの信号でも窓長が違うため `10 log10(80/170) = -3.2736 dB` となり、0 dB は中立や無残響を意味しない。
これは提案式の数値計算による確認である。

## 3. DECAY の推定対象と時間計算

onset から次の onset までの区間は、自由減衰区間と同義ではない。
持続音、打弦音の自然減衰、フェード、コンプレッサーの release もその区間に入る。
特に残響のない指数減衰音でも、dB 包絡線は直線になり、理想条件なら R² = 1 となる。
R² ≥ 0.9 は直線への適合度を示すが、減衰の原因が残響であることは示さない。

提案書 §4.3 の外挿計算には誤りがある。
−5 dB から −25 dB までの 20 dB 区間を使う場合、60 dB 外挿時間はその区間長の 3 倍になる。
10 個の点が必要なら点間は少なくとも 9 区間なので、10 ms 刻みで 270 ms、30 Hz で 900 ms が外挿時間の算術上の下限になる。
提案の 150 ms と 400 ms は、この条件を満たさない。
この下限も精度保証ではなく、FFT の約 85 ms 窓とフレーム間の重なりを含めた検証が必要である。

提案書 §4.4 と §6.2 の「履歴 6 秒なので 6 秒超の DECAY は測れない」も外挿式と整合しない。
例えば T60 = 8 秒の理想的な指数減衰では、−5 dB から −25 dB の区間長は約 2.667 秒で、onset から −25 dB までも約 3.333 秒に収まる。
6 秒を製品上限にすること自体は選択できるが、保持時間から導かれる測定不能条件とは分ける必要がある。
まず負の傾き、連続した観測区間、実際に観測した dB 幅、ノイズ床からの余裕を検証し、観測時間と外挿時間を別々に保持する。

## 4. DEPTH の知覚的な意味

EARLY 分布の IQR が大きいことから、音源の前後位置が広がっているとは断定できない。
残響も位置も変えずに、短く減衰するドライ音と長く持続するドライ音を交互に鳴らすだけで EARLY の分布は広がる。
提案式の指数包絡線を積分すると、T60 相当 0.3 秒と 2 秒の音では EARLY はそれぞれ約 15.89 dB と 0.28 dB となる。
この差に空間処理は必要ない。

逆に、複数の距離感を含む同じ和音が繰り返されれば、ミックス全体の onset ごとの EARLY はほぼ同じになり得る。
前後位置を持つ各音源を分離せず、混合信号のイベント差を見ているためである。
「平面的」「奥行きがある」という UI 解釈や M8 達成の主張には、音色、音価、編成、強弱を統制した聴取実験が要る。

## 5. REPEAT とディレイの区別

自己相関のピークは、エコーだけでなく演奏の周期にも生じる。
ホスト BPM に一致するラグを除く方法では、テンポ同期ディレイも同時に除いてしまう。
倍音に相当する周期、拍の分割、複数タップ、テンポ変化、強いラグゼロ近傍を含めた候補選択が必要になる。

提案書 §6.4 の「ピーク高さ [dB]」には、どの自己相関を正規化し、何を基準に対数化するかの定義がない。
dB 包絡線を使うのか線形パワーを使うのか、平均除去、ラグごとの重複長補正、最小 prominence も明示する必要がある。
試作するなら、まず「反復周期の候補」として評価し、ディレイ量の測定とは分離する。

## 6. PRE/POST 差分と Reference

提案書 §7 の「既存 Δ 経路にそのまま載る」は現行契約と一致しない。
SPACE は `HyphaObservatoryContract.h` と `HyphaObservationPageContract.h` で絶対値に固定されている。
新しい差分には、共通イベント、同一測定窓、チャンネル定義、サンプル時刻、世代、双方の有効性を運ぶデータ契約が必要になる。
別々に採用した PRE 候補群と POST 候補群の四分位値を引くと、候補選択の違いまで処理差として混ざる。
片側でだけ検出した onset、既存 ATTACK の局所イベント対応、遅延補償の扱いも再検討する。

対応を正しくしても、「このチェーンが残響を +0.4 秒足した」とは限らない。
EQ による帯域比の変化やコンプレッサーの release でも、観測した包絡線の傾きは変わるためである。
支持できる表現は、定義した同一区間の「観測減衰時間の差」である。
同じ理由で Δ REPEAT は「ディレイを足した量」ではない。

Reference 比較についても、定数ゲインに対する数式上の不変性と、異なる楽曲間の比較可能性は分ける。
実装上のノイズ床や onset 閾値によって採用イベントが変わることもある。
RUN／WORK／TARGET の保存形式と比較可能条件、Reference 専用の非 RT 解析、欠測時の表現を定義するまで、R4／M8／M9 が埋まったとは扱わない。

## 7. 帯域入力の取り違え

提案書 §3.2 の `perceptual/tables_psb.rs` は現行パスではなく、実在する `phase_d/tables/tables_psb.rs` は 24 帯域の境界表である。
256 個の表示用 Spectrum 値を、240 個の specific loudness 値として扱うことはできない。
今回追加した表示 PSB も、0–24 Bark を 20 グループにまとめた正規化比率であり、帯域エネルギー履歴とは異なる。

正規化した比率は、全帯域が同率で減衰すると変化しない。
そのため、表示 PSB から減衰率を計算する流用は成立しない。
帯域別 DECAY には、窓関数と帯域幅を定義した非正規化パワーが必要であり、dB 値の単純加算も避ける。
`20 × 180 × 4 = 14,400 bytes` は配列一つ分の計算として正しいが、PRE/POST、チャンネル、時刻、世代、品質情報、候補の保持を含む総メモリ見積もりではない。

## 8. 文献と新規性の主張

Ratnam らの原論文は、指数減衰する確率モデルと最尤推定を使い、蓄積した分布から候補を選ぶ研究である。
ヒストグラムの最初の主要ピークを使う記述は確認できたが、提案の単純回帰と下位四分位を音楽全般に適用した精度保証ではない。
論文自身も音声の自然減衰や短い無音区間による推定誤差を述べている。
したがって、研究を参照することと、提案アルゴリズムの精度を実証したことは区別する。[Ratnam らの原論文](https://www.brl.uiuc.edu/Publications/2003/Ratnam-JASA-28772003.pdf)

参考文献にはリンクの不一致が一つある。
`mack20_interspeech.html` は DRR を DNN のマスク推定で求める 2020 年の論文であり、記載された T60 推定論文ではない。[実際の 2020 年論文](https://www.isca-archive.org/interspeech_2020/mack20_interspeech.html)
後者の題名に対応する文献は Löllmann らの 2015 年の論文である。[著者所属機関の書誌情報](https://cris.fau.de/publications/123251964/)

提案書 §2.2 の Ts は「エネルギーの半分が到達する時刻」ではなく、二乗インパルス応答の時間重心である。
中央値と重心は別の量なので、定義を修正する必要がある。[REW 公式のパラメーター説明](https://www.roomeqwizard.com/help/help_en-GB/html/graph_rt60.html)
ISO の公開概要は室内音響パラメーターの測定規格であることを確認できるが、Table A.1 の JND 数値自体はこの精査では原規格本文で確認できていない。
仮に知覚閾値を確認しても、それをそのまま推定器の誤差保証や表示分解能の根拠にはできない。[ISO 3382-1 の公式概要](https://www.iso.org/standard/40979.html)
本文で扱う ISO 3382-1 と参考文献にある ISO 3382-2 も別の部なので、参照対象を揃える必要がある。

列挙した数製品に機能が見当たらないことから、「製品が存在しない」「Hypha でしか作れない」は証明できない。
PRE/POST 形式は同時比較の利便性を持つが、録音した処理前後を別々に測って比較する方法まで原理的に排除しない。
市場全体の不存在、新規性、聴感項目の達成は未確認として扱う。

## 9. 表示と処理契約の漏れ

§10 は観測数の併記を必須にしているが、375×250 の表示表には DECAY 一値しかない。
300×200 では subview が非表示になるため、「5 サイズすべてで意味を持たせる」との関係も未定義である。
文字を小さくして詰め込まず、最小サイズで扱える機能、観測数と更新時刻の置き場、欠測の説明を先に決める必要がある。
候補が増えない間に最後の値だけが残る場合も、現在の音から得た値と誤認しない表示が要る。

§11 の onset 到着時と view を開いた時だけの更新では、未来 250 ms を使う EARLY や、その後の減衰区間の確定条件が不足する。
候補の開始、観測窓の完了、棄却、停止時の未完了処理を独立した状態として定義する。
計算を Audio Thread の外へ出すだけでなく、既存の Watch／Record 計測を待たせない実行単位と上限も必要である。
解析を非表示でも継続するのか、表示時だけ蓄積するのかを決め、候補の有効期間と解析オーナーの寿命を一致させる。

## 10. 実装判断の前に必要な検証

指数減衰ノイズは、既知の傾きを再現するテストとして残す。
ただし、合成ノイズ一種類で ±5% に入っても、完成済み音楽の残響を測れた証拠にはならない。
次の判定を別々に記録する必要がある。

1. **数式の正しさ**：固定 seed の複数ノイズ、複数レベルと sample rate、減衰時間、開始ビンの位相、非指数の二段減衰を使う。
2. **誤認の検出**：残響なしのドライな減衰音、サステイン、フェード、gate、compressor release、EQ、拍に同期した dry 音列を含める。
3. **欠測の正しさ**：無音、定常ノイズ、ノイズ床への到達、次 onset、窓途中の停止、seek、片側の欠測、解析枠不足を含める。
4. **比較の正しさ**：同じイベント集合、同じ窓とチャンネル定義、PRE/POST 同値、定数ゲイン、遅延既知／不明、Reference 欠損を確認する。
5. **実素材での有用性**：採用率、誤差分布、採用イベント数、観測した dB 幅、推定の年齢、音色や編成への依存を示す。
6. **製品境界**：原音 bit identity と 0 samples latency、既存 Record との分離、解析オーナー上限、CPU とメモリ、再起動と editor close、5 サイズの読みやすさを検証する。

提案する順序は、定義と表示上の主張を確定し、EARLY と DECAY のオフライン試作で誤認を評価してから、オーナーと保持の設計を選ぶことである。
DEPTH を先に公開して M8 を達成扱いにする順序は、現時点の根拠では勧めない。
観測数に加えて採用条件と比較可能性を確立することを、SPACE への統合判断の前提にする。
