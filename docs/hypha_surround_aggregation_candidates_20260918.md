## 0. 先に区別すべきこと — 入力の集約か、結果の集約か

調査の過程で、**2 種類の集約が混在している**ことが分かった。

| 種類 | 何を畳むか | 例 |
|---|---|---|
| **入力の集約** | 検出・解析の**前**に信号を畳む | Attack の LR mode（power spectra を畳んでから 1 本の ODF） |
| **結果の集約** | 各チャンネルを**独立に測ってから**値を畳む | `phase_d`（チャンネル別 sharpness の算術平均） |

**この 2 つは Nch で別の問題になる。**

- 入力の集約は「畳んだ信号は何か」が問われる。
- 結果の集約は「別々に測った値を足す意味は何か」が問われる。

`phase_d` が後者であることは `channels.rs:3-5` のコメント自身が述べている
（非線形処理の前に混ぜると逆相が消えるため、独立に測る）。

## 1. 現行定義（コードから / 式）[A]

| 指標 | 式 | 窓 | 場所 |
|---|---|---|---|
| Correlation | `Σ(L·R) / √(E_L · E_R)`、`[-1, 1]` へ clamp。**DC 除去なし（uncentred）** | 3 s | `stereo_meter.rs:357-360` |
| Balance | `10·log10(E_L / E_R)`。状態は Numeric / LeftOnly / RightOnly / Unavailable | 3 s | `:347-355` |
| MONO | 帯域ごとに `10·log10(Pm / (Pm + Ps))`。`M=(L+R)/2`、`S=(L−R)/2` を**時間領域**で作ってから FFT | 1/3 oct 32 band | `mono_sum.rs` |
| Attack（LR mode） | **2 本の power spectrum の平均**を 1 本の ODF にしてから検出 | window 4,096 | `transient_superflux.rs:366-386` / `:465-478` |

**`AttackEvent` にチャンネル識別が無い**（`attack_runtime_state.rs:93-101`）。
`generation` / `sample_rate` / `channels` / `event_sample` / `value` は持つが、
**「どのチャンネルで起きたか」を表す場所が無い。**

## 2. Attack — `0.5*(a+b)` は N へ一般化しない [A]

```rust
crates/kirin_measure/src/transient_superflux.rs:474-477
*output = if average {
    0.5 * (*output + value)
} else {
    value
```

チャンネルを順に流し込む形なので、**N ch へそのまま広げると後のチャンネルほど重くなる。**

| ch 数 | 各チャンネルの実効重み |
|---:|---|
| 2 | 0.5000 / 0.5000 |
| 3 | 0.2500 / 0.2500 / **0.5000** |
| 6 | 0.0312 … 0.2500 / **0.5000** |
| 12 | 0.0005 … 0.2500 / **0.5000** |

**12ch では最後のチャンネルが全体の半分を占める。** 和は 1.0 のままなので、
**数値は「もっともらしく」出続ける。** §3 の G と同じ形である。

> **現行の Attack LR mode は 2ch でのみ正しい平均であり、
> ガードを外しただけでは N ch の平均にならない。**

### 2.1 候補

| 案 | 内容 | 保つもの / 失うもの |
|---|---|---|
| **(A-1) 正しい N 平均** | `Σ power / N` にして 1 本の ODF を作る | 現行の「1 イベント列」を保つ。**チャンネル識別は依然として無い** |
| (A-2) チャンネル別検出 | チャンネルごとに ODF を作り、イベントに識別を持たせる | 識別が得られる。**ABI と表示に「N 本のイベント列」を置く場所が要る** |
| (A-3) 選択チャンネルのみ | selector で選んだ 1 チャンネルを検出する | 契約表 §11 の view モデルと一致。**全体の同時把握を失う** |

**推奨: 初期版は (A-3)。** 根拠:

1. **Spectrum / Sharpness / Attack は同じ 3 view モデルを共有する**（契約表 §11.6 に Attack を追加）。
   `SuperFluxChannelMode::Lr / Mid` が存在する時点で、Attack も view 選択型である。
   **selector 拡張が 3 つ同時に効く。**
2. **集約を発明しない。** (A-1) は「N 平均」を新たに定義することになる。
   2ch の平均が妥当だったことは、12ch の平均が妥当であることを意味しない。
3. (A-2) は表示設計が要る（契約表 §11.4 の「全チャンネル同時表示」と同じ課題）。

**(A-1) は「現行の意図を N へ正しく直す」案として残す。**
採るなら **`0.5*(a+b)` の逐次形を `Σ/N` へ直す**ことが前提である。

### 2.2 (A-3) の名称 — 「選択 view の Attack」である

**内部契約上の名前を `ATTACK` にしない。**

> **Attack of selected view.**
> C を選べば C の Attack、Lss を選べば Lss の Attack である。
> **Hypha はこれを「作品全体の Attack」とは解釈しない。**

この一文を契約として残す。**表示名が短くても、記録される意味は選択 view に限定される。**

**そして、(A-3) を採るということは次を意味する。**

> **初期 Nch 版に「作品全体の Attack」という集約指標は存在しない。**

これは欠落ではなく、**発明しないという決定の帰結**である。利用者向けにも、内部記録上も、
「サラウンド mix の Attack」を名乗る値を出さない。必要になったときは (A-1) / (A-2) を
**新しい mode 名**で追加する（§2.3 のとおり `definition_hash` が旧定義と混ぜない）。

### 2.3 `SuperFluxChannelMode` の実 read [A]

承認前に閉じるべき項目を確認した。

```rust
crates/kirin_measure/src/transient_superflux.rs:27-31
pub enum SuperFluxChannelMode { Lr, Mid, Side }
```

**variant は 3 つだけ。** Spectrum / Sharpness と同じ 3 view である。

```rust
crates/kirin_measure/src/transient_superflux.rs:36-38
Self::Lr  => "lr-power-mean",
Self::Mid => "mid-waveform",
```

```rust
crates/kirin_measure/src/transient_superflux.rs:454
bin.re = 0.5 * (left + right_sign * right) * window;
```

**Mid / Side は波形領域で `0.5·(L ± R)`。** Sharpness の `analyze_mono` と同じ形であり、
**2ch 前提である**（契約表 §11.5）。`Side` は `channel_count == 1` を拒否する（:88）。

**3 variant の実体（:366-408 / :465-480 実読）:**

| mode | 集約の場所 | 実体 |
|---|---|---|
| `Lr` | **パワー領域** | L と R を別々に FFT し、`write_power(average=true)` が `0.5·(prev + value)`。**スペクトルの平均** |
| `Mid` | **波形領域** | `0.5·(L + R)` を 1 回 FFT |
| `Side` | **波形領域** | `0.5·(L − R)` を 1 回 FFT |

**3 つとも 2 信号でしか定義されない。** `Lr` の逐次平均は N へ一般化すると
`0.5·(0.5·(a+b)+c)` になり、**先に入れたチャンネルほど軽くなる**（§2 の指摘）。
`Mid` / `Side` は M/S 分解そのもので、N には対応物が無い。

**したがって (A-3) の条件「mode 全体の監査」はここで閉じている。**

**そして集約規則は既に測定の同一性に入っている。**

```rust
crates/kirin_measure/src/transient_superflux_bank.rs:63-
hasher.update(config.channel_mode.as_str().as_bytes());   // "lr-power-mean" 等
hasher.update((config.channel_count as u64).to_le_bytes());
```

`definition_hash` は **channel_mode の文字列と channel_count の両方**を含む。

含意:

- **集約規則を変えれば hash が変わり、旧測定と新測定が区別できる。**
  `"lr-power-mean"` という名前自体が、**LR mode が平均であることを識別子に刻んでいる。**
- **チャンネル数も既に hash に入っている。** 2ch と 6ch の Attack は既に別の定義として区別される。
- したがって **Attack には「何をどう集約したか」を記録する場所が既にある。**
  (A-1) を将来採る場合も、**新しい mode 名を与えれば旧定義と混ざらない。**

## 3. Correlation — 現行値は 2 信号の関係である

`Σ(L·R) / √(E_L·E_R)` は**2 つの信号の間**にしか定義されない。
N ch へ「一般化」する対象が無い。**拡張ではなく追加である。**

| 案 | 内容 | 保つもの / 失うもの |
|---|---|---|
| **(C-1) 左右対のみ** | layout の左右対それぞれに現行式を適用（5.1 は 2 本、7.1.4 は 5 本） | **現行式をそのまま使う。** 同じ downmix 出力へ合流する別の組合せ（L と C 等）を見落とす |
| (C-2) 選択ペア | selector で 2 チャンネルを選ぶ | 任意の組合せを見られる。**常設 overview を失う** |
| (C-3) 全ペア行列 | 12ch で独立 66 組 | 網羅的。**表示設計が要る。競合（Halo Vision）が既に持つ領域** |

**推奨: (C-1) を overview、(C-2) を詳細。** 根拠:

1. **(C-1) は現行式を変えない。** 新しい測定量を定義せずに済む。
2. 左右対は **Hypha が置いた規則**（§4.2.1 / D-10 の mirror 判定）を交渉済み layout の role へ
   適用して機械的に導出する。**規格が対を決めるのではない。** BS.2051-3 が定めるのは
   speaker position と label であって、Correlation 用の pair 集合ではない。
   決定性は「layout から一意」ではなく「規則を明示したから一意」である。
3. (C-3) は findings §6 のとおり競合が既に持つ領域であり、
   **Hypha の固有価値はそこではない**（計画 §12）。

**注意**: 現行式は **DC 除去をしていない**（uncentred）。
N ch へ適用対象を増やすとき、**この定義を変えない**（契約表 §17 の「定義を変えない」規律）。

### 3.1 overview は事実の集合であり、1 つの値ではない

**「overview」という語を、単一値へ畳んでよい根拠にしない。**

7.1.4 で 5 本の correlation が出たとき、それを `CORR 0.74` のような 1 つの数へ戻してはならない。
平均・最小・worst pair の**どれを採っても、それは新しい集約指標である**（D-6 の「集約を発明しない」に反する）。

overview の表示要件:

```
L/R +0.91   Lss/Rss +0.64   Lsr/Rsr +0.22   TFL/TFR +0.88   TRL/TRR +0.41
```

**値と対の身元を分離しない。** どの対の値かが消えた瞬間、その数は何も特定していない。

**Balance（B-3）にも同じ規律が効く。**

## 4. Balance — 「左右」の定義が layout で変わる

`10·log10(E_L / E_R)` は L と R という**2 チャンネル**の比である。

| 案 | 内容 | 保つもの / 失うもの |
|---|---|---|
| (B-1) L/R のみ | layout に L と R があればそれだけを比べる | 現行式そのまま。**Ls/Rs、Lss/Rss を無視する** |
| **(B-2) 左右グループ** | 非 LFE の左側群と右側群のエネルギー比 | 全チャンネルが寄与する。**Center 主体の mix でも 0 dB になり得る** |
| (B-3) 左右対ごと | 対ごとに balance を出す（5.1 は 2 本、7.1.4 は 5 本） | どの層が偏っているか分かる。**単一値を失う** |

**推奨: (B-3)。** 根拠:

1. **(B-2) の問題は契約表 §7 で既に指摘した。** Center を除くと Center 主体でも 0 dB になる。
   「左右成分の balance」ではあっても「全体の spatial balance」ではない。
   **単一値にすると、その区別が表示から消える。**
2. **(B-3) は Correlation の (C-1) と同じ「左右対」の単位を使う。**
   2 つの指標が同じ分解単位を持てば、**利用者が対応付けられる。**
3. **(B-1) は現行式を保つが、サラウンドで surround 層の偏りを見逃す。**

**(B-2) を採る場合は、C と LFE を分母に入れない事実を表示・記録する**（契約表 §10.4 と同じ規律）。
そこでは「除外」が実際に行われる操作だからである。

**(B-3) では「C / LFE を除外した」と書かない。** B-3 の測定量は指定された 1 対のエネルギー比であり、
C と LFE は**その対の構成員ではない**。全体エネルギーから何かを意図的に捨てて作った値ではない。
正確には次になる。

> **Balance 値には対象 pair を必ず記録する。pair 外のチャンネルはこの測定量の入力ではない。**

この差は表示にも出る。「除外」と書くと、利用者は「全体の balance から C を抜いた値」と読む。
B-3 はそもそも全体の balance ではない。

### 4.1 Correlation と Balance は同じ pair 定義を参照する

(B-3) と (C-1) は**同じ「左右対」**を単位にする。
これを別々に列挙すると、**2 つの指標が違う対を見ている状態が起こり得る。**

共通の記述を 1 つ置く（名前は提案）:

```
PairRole {
    left_channel_role,
    right_channel_role,
}
```

**Correlation と Balance が同じ `PairRole` の並びを参照する。**
これで両者の食い違いを**構造的に**防ぐ。表示上の対応付けも自動的に取れる。

7.1.4 での例（§4.2 の導出規則による）:

```
FRONT      L ↔ R
SIDE       Lss ↔ Rss
REAR       Lsr ↔ Rsr
TOP FRONT  TFL ↔ TFR
TOP REAR   TRL ↔ TRR
```

**何を比較しているかが表示から消えない。**

### 4.2 左右対は role から機械的に導出する — 手で決めない

**`channel_count == 12 だから 5 pair` としない。**

```
交渉済み layout に存在する role を確認
  → 対応する mirror role が存在するときだけ pair を生成
```

- **未知 layout へ勝手に pair を作らない。**
- mirror が無い role（C / LFE / 天井の中央等）は **pair に入らない**。それが事実である。
- 契約表 §11.3.1 のとおり **selector も role で指す**。
  **この role vocabulary を Correlation / Balance / Attack / Spectrum / Sharpness で共通化する。**

**Daisuke が手で対を列挙する項目にしない。**

#### 4.2.1 mirror の判定規則 — 方位角の符号反転で足りる

**対の表を書かない。規則を 1 つ置く。**

> **mirror(role) = 同じ平面（M / U）で方位角の符号を反転した role。**
> **方位角が 0° または 180°（正中面）なら mirror は無い。LFE にも mirror は無い。**

ITU の角度表記がそのまま使える（findings §2 の対応表）。
`L = M+030` の mirror は `M−030 = R`。`Lss = M+090` の mirror は `M−090 = Rss`。
`C = M+000` と `Cs = M+180` は正中面なので mirror が無い。

**左を方位角が正の側とする**（ITU の `M+030` が左という表記に従う）。

#### 4.2.2 導出結果 [A]

この規則を交渉済み layout に当てた結果（`channel_positions[]` の存在判定のみ）:

| layout | pair 数 | 対 | 対の無い role |
|---|---:|---|---|
| 5.0 | 2 | L↔R, Ls↔Rs | C |
| 5.1 | 2 | L↔R, Ls↔Rs | C, LFE |
| 7.1 | 3 | L↔R, Lss↔Rss, Lsr↔Rsr | C, LFE |
| **7.1.4** | **5** | L↔R, Lss↔Rss, TFL↔TFR, TRL↔TRR, Lsr↔Rsr | C, LFE |
| 9.1.6 | 7 | 上記 + WL↔WR, TSL↔TSR | C, LFE |

**7.1.4 の 5 対は、§4.1 で手で書いた並びと一致する。** 規則だけで再現できる。

#### 4.2.3 pair 数も layout を特定しない

findings §3.1 の「チャンネル数で layout を特定してはならない」は、**pair 数にも当てはまる。**

| layout | ch | pair 数 | 対 |
|---|---:|---:|---|
| 7.1 | 8 | **3** | L↔R, **Lss↔Rss, Lsr↔Rsr** |
| 5.1.2 | 8 | **3** | L↔R, **Ls↔Rs, TSL↔TSR** |
| 5.1.4 | 10 | **4** | L↔R, **Ls↔Rs, TFL↔TFR, TRL↔TRR** |
| 7.1.2 | 10 | **4** | L↔R, **Lss↔Rss, Lsr↔Rsr, TSL↔TSR** |

**同じチャンネル数で pair 数まで一致し、対の中身だけが違う。**

したがって **`PairRole` の並びは role の同一性で比較する。** 個数や index では比較しない。
契約表 §11.3.1 の selector と同じ理由である
（layout 変更を検出できないと、別の対の履歴が無言で連結する）。

## 5. MONO — サラウンドでは適用外。downmix 観測は別の新規測定へ

現行 MONO は `M=(L+R)/2` / `S=(L−R)/2` に対する帯域別の残存比であり、
**L/R という 2 チャンネルの定義**である（契約表 §6）。

| 案 | 内容 | 保つもの / 失うもの |
|---|---|---|
| (M-1) 適用外 | Nch では出さない | 最も安全。**サラウンドで「mono 互換性」を見る手段が無くなる** |
| (M-2) 左右対ごとの MONO | 対ごとに現行式を適用 | 現行式そのまま。**layout 全体の downmix 生存は見えない** |
| (M-3) 旧案「MONO の Nch 版」 | 現行式を Nch へ広げる | **成立しない。** §5.1 |

**推奨: MONO は (M-1)。サラウンドでは適用外を明示する。**

1. **現行 MONO の名前を残して意味を差し替えない**（契約表 §6）。
2. **意味が確定していない値を出さない**。機能後退ではなく Hypha の原則である。
3. (M-2) は現行式を保つが、**「mono 互換性」という名前で対ごとの値を出すのは誤解を招く。**

### 5.1 現行 MONO 式は Nch へ広がらない

```
現行:  帯域ごとに  10·log10( Pm / (Pm + Ps) )
       M = (L+R)/2、S = (L−R)/2
```

**分母 `Pm + Ps` は M/S 分解が持つエネルギー関係を使っている。**
一般の Nch → stereo downmix では、**同じ分母を作れない。**

> **したがって downmix survival を「現行 MONO 式の Nch 版」として設計してはならない。**

### 5.2 Downmix Observation は MONO の後継ではなく、独立した新規測定である

**MONO の承認と切り離す。初期 5.1 で新しい "surround MONO" を作らない。**

設計するなら**ゼロから**、次を別々の事実として保持する。

| 保持する量 | 内容 |
|---|---|
| **source-band energy** | 入力側の帯域エネルギー（基準量） |
| **rendered / downmixed-view band energy** | 明示 downmix を通した後の帯域エネルギー（実測量） |
| **差分** | 上の 2 つの関係 |

**最初から 1 つの「survival %」を作らない。** 事実を保持してから、何を製品表示するか決める。

理由は `P_downmix / P_source` でも足りないことにある。
**Nch 側の各チャンネルのエネルギーを単純加算した値と downmix 後のエネルギーは、
係数だけでなくチャンネル間の相関と位相で変わる。**

**そしてそれこそが downmix survival が観測したい現象である。**
単一比に畳むと、観測したかった情報がその場で失われる。

### 5.3 位置づけ

- **単なる mono compatibility ではない。**
- **「ある明示された render / downmix を通したとき、何が帯域ごとに変化したかを観測する」**
  というサラウンド向けの測定である。
- 係数の出典（契約表 §10.6）と規格側の downmix 調査が揃ってから設計する。

**MONO の「undefined と floor の区別」（INV-S31 / 契約表 §17.3）は、
新測定でも同じ規律として引き継ぐ。**

## 6. 4 件は「同じ未定義」ではない — 深さが違う

4 件とも AGGREGATION-UNDEFINED だが、**決めなければならないものの層が違う。**

| 指標 | 決める対象 | 層 |
|---|---|---|
| **Attack** | 検出の**前**に何を入力とするか | 入力の集約 |
| **Correlation** | 既存式を**どの対へ**適用するか | 対の選択 |
| **Balance** | 既存式を**どの対 / 群へ**適用するか | 対・群の定義 |
| **Downmix Observation** | **式そのもの**。測定量がまだ存在しない | 測定量の定義 |

上 3 件は**既にある式の適用範囲**を決める作業である。対象を決めれば値は出る。

**Downmix Observation だけが一段手前にある。** 「何に対する残存か」（分母）が決まっていない以上、
比較すべき候補が並んでいない。**候補比較と呼べる段階にまだ達していない。**

したがって承認の単位を 2 つに分ける。

### 6.1 承認事項 3A — 現行測定量の Nch 適用範囲

**今決められる。** 新しい音響指標を発明せずに初期 5.1 対応を閉じられる。

| 指標 | 初期版の推奨 | 条件 | 後続 |
|---|---|---|---|
| Attack | **(A-3) 選択 view のみ**（selector 拡張で 3 指標同時に解決） | §2.3 の mode 監査は完了済み | (A-1) 正しい N 平均 / (A-2) チャンネル別イベント |
| Correlation | **(C-1) 左右対 overview + (C-2) 選択ペア詳細** | §3.1 の単一値化禁止を併せて守る | (C-3) 全ペア行列 |
| Balance | **(B-3) 左右対ごと**（Correlation と同じ分解単位） | pair identity を値と分離しない | 単一値が要るなら (B-2) を別途定義 |
| MONO | **(M-1) 適用外を明示** | — | — |

### 6.2 承認事項 3B — 新規サラウンド観測（まだ Research）

**これらは候補比較ではなく、測定量を定義する作業である。** 初期 5.1 対応の前提条件にしない。

| 項目 | 現状 |
|---|---|
| N 平均 Attack / 空間的 Attack イベント集約 | 測定量未定義 |
| 全ペア correlation 行列 | 表示設計と競合比較が未了（findings §6） |
| 群 Balance | (B-2) の意味論が未決（§4） |
| **Downmix Observation / Downmix Survival** | **分母が未定義。§5.2 の 3 事実を先に固定する** |

**3B を 3A の承認条件にしない。** 分けないと、初期 5.1 対応のために新しい音響指標を
急いで発明することになる。

**共通する根拠:**

1. **集約を発明しない。** 4 件とも「新しい平均を定義する」案を初期版から外した。
2. **既存の view モデルに乗せる。** Attack を selector 側へ寄せると、
   Spectrum / Sharpness / Attack が同じ形で閉じる。
3. **左右対を共通の分解単位にする。** Correlation と Balance が対応付く。
4. **係数が要るものは係数が揃うまで確定しない。**
