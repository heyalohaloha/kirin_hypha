# Hypha サラウンド化 — 推奨実装計画

Status: 推奨計画。着手は Daisuke の承認後。工数・日程は材料にしない（R-27）。

Date: 2026-09-18

Branch: `claude/eager-pascal-edacak`

前提事実は `@docs/hypha_surround_channel_map_findings_20260918.md`（B-921 / B-922）に置く。
矛盾時は findings を優先する。本書は、その事実から導ける**順序と推奨**だけを書く。

## 0. 目的

サラウンド化の中心は「12 チャンネルを受け取れること」ではない。
**どの位置の信号を、どの条件で測ったのかを誤認なく残せること**である。

現状の最大の危険は、チャンネルを増やすと `ebur128` の default channel map によって
**エラーを出さずに測定値が小さい側へずれる**ことである（findings §3）。
7.1.4 で 12 本中 6 本、9.1.6 で 16 本中 10 本が loudness に寄与しない。

したがって本計画は、**機能追加より先に「無言で間違えないこと」を作る**順序を取る。

## 1. 推奨の要旨

| # | 論点 | 推奨 | 根拠 |
|---|---|---|---|
| 1 | 対象レイアウト | **5.1 を先に通し、7.1.4 は資料が入ってから** | 5.1 は公式 EBU test set で**今日検証できる唯一のサラウンド**（findings §4）。7.1.4 は BS.2051 の角度表が無いと map を確定できない（findings §7） |
| 2 | 参照版 | **一本化せず、測定ごとに使った版を記録する** | Apple の Atmos 納品は BS.1770-4 参照、ITU 現行は -5 で一致していない（findings §6.1）。Annex 1/2 に差分は無いので mono/stereo の数値は変わらない |
| 3 | ABI の形 | **固定最大 `KIRIN_MAX_CHANNELS = 16` + `channel_count`** | 既存 ABI は固定 offset の POD で、parity test がその offset に依存する。可変長は成立しない。`mono_sum_db[32]` と同じ形。16 は 9.1.6 まで届き、二度目の ABI 破壊を避けられる |
| 4 | 未知レイアウト | **受理しない（推測で map を当てない）** | AGENTS.md:175。チャンネル数ではレイアウトを特定できない（8ch に 7.1 と 5.1.2、10ch に 5.1.4 と 7.1.2 / findings §3.1） |

## 2. Phase 分割

外部資料に依存する Phase を最後にまとめ、それ以外は今日から進められる形にした。

### Phase S-0 — 無言欠落を不可能にする（外部資料 不要）

サラウンドを 1 本も受理しない今の状態でも、先にこれを置く。

- `hypha::channel_map` を新規に置く（1 ファイル / 500 行以内）。
  JUCE `AudioChannelSet` → `ebur128::Channel` の**明示テーブル**。
- レイアウト判定は `AudioChannelSet` の**同一性**で行う。**チャンネル数では判定しない。**
- テーブルに無いレイアウトは `isBusesLayoutSupported` で拒否する。
  これは R-28 の「無言 skip」に当たらない。利用者がそのトラックに挿す操作の結果として、
  ホストが挿せないことで明示される。
- `MeasureEngine` 生成直後に `set_channel_map` を必ず呼ぶ。
  `change_parameters` は使わない。使う場合は**直後に map を再設定する**
  （`vendor/ebur128/src/ebur128.rs:462` はチャンネル数が変わると map を捨てる）。

**gate**: 各レイアウトについて map の全要素が期待値と一致することを固定する。
negative check を必ず行う — 1 要素をわざと `Unused` に変えてテストが落ちることを確認する。

### Phase S-1 — ABI を N チャンネル化（外部資料 不要 / レイアウト決定に依存しない）

- `KIRIN_MAX_CHANNELS 16` と `channel_count` を追加。
- `KirinMeterSession` の `[2]` を `[KIRIN_MAX_CHANNELS]` へ（8 本 / findings §5）。
  `kirin_hypha_ffi.h:164 clip_event_count`、reference index / visual の `[2]` も同様。
- `channel_count` を超える要素は**読まない**契約にし、埋め値は double は NaN、整数は 0 とする。
  NaN は「測っていない」であって「0 dB」ではない（既存 MONO と同じ規律 / INV-S31）。
- size assert は 1 箇所（`HyphaObservationEquality.h`）に集約済み（B-923）。増やさない。

**数字（概算 / 実装時に実測して invariant へ記録する。R-10）**:
`uint8[2]→[16]` が +14、`double[2]→[16]` と `uint64[2]→[16]` が各 +112。
8 本で +798。`KirinMeterSession` 1008 → 約 1808、`KirinObservatoryFrame` 1248 → 約 2048。
表示更新は 10 Hz なので転送量としては問題にならないが、**概算のまま確定させない。**

### Phase S-2 — 5.1 を通す（外部資料 不要）

- `isBusesLayoutSupported` に `create5point1()` と `create5point0()` を追加。
- `StereoMeter::new` の `1..=2` を、レイアウト記述を受け取る形に置き換える。
- `channels == 2` の 17 か所（findings §5）を、2ch 前提のまま残すもの／一般化するものに分けて一括処理する。
  パッチの積み重ねにしない。

**gate（ここが S-0 の正しさの証拠になる）**:
既存の `ebu_v05_reference.rs` の 5ch / 6ch 素材が、**default map ではなく明示 map 経由でも
LUFS-I −23.0** になることを固定する。
今は偶然通っている（findings §4）。明示 map にしても同じ値が出ることが、テーブルが正しいことの根拠になる。

### Phase S-3 — 記録の分離（外部資料 不要）

次を**それぞれ別の項目**として持つ。不明な項目は推測で埋めず、不明のまま残す。

- 入力レイアウト
- 実際に適用したチャンネルマップ
- レンダラーの前後どちらを測ったか
- レンダリング条件（分かる場合）
- 規格の参照版
- 測定エンジンの版

BS.1770-5 Annex 4 が「使用したスピーカー配置とレンダリングアルゴリズムを報告する」ことを求めており
（findings §6.2）、この分離は規格側の要請とも一致する。

R-22: これらは事実の記録であって、適合判定を出さない。

### Phase S-4 — 2MIX 専用計測の置き換え（外部資料 不要 / 5.1 で成立する）

`correlation` / `balance` / `MONO` / MID-SIDE は 2ch 前提で作ってある。

- **correlation** — N×N 行列は UI に載らない（7.1.4 で 144 セル）。**左右対に限定する。**
  5.1 は L/R, Ls/Rs の 2 本。7.1.4 は L/R, Lss/Rss, Lsr/Rsr, TFL/TFR, TRL/TRR の 5 本。
  対の数はレイアウトから決まるので、S-0 のテーブルにペア定義を持たせる。
- **balance** — 左半分と右半分のエネルギー比。中央と LFE は分母に入れない。
- **MONO** — **downmix survival** へ拡張する。
  帯域ごとに、指定した downmix を通した後で何が残るかを dB で出す。
  既存の split scale（0..−6 / −6..−24）、6 秒 field、句単位の行折れをそのまま再利用できる。
  downmix 係数は規格依存なので、**使用した downmix を記録する**（S-3 と同じ原則）。
- R-12: downmix は測定のための内部計算であり、出力音声は加工しない。既存 MONO と同じ扱い。

**「競合と同等以上」の実体はここにある。** findings §6 で確認した範囲では、
競合は loudness / True Peak / correlation を出している。帯域別の downmix 生存は見当たらない。
ただし「競合が出していない」と断定はしない — 確認した資料の範囲でそう読める、に留める。

### Phase S-5 — 7.1.4（BS.2051 角度表と Annex 3 configuration 対応が入ってから）

- S-0 のテーブルに 7.1.4 行を足すだけで済むよう、S-0 を設計する。
- **gate が難しい**: 公式 test set に 7ch 以上の素材が無い（findings §4）。
  各チャンネル単独に既知レベルを入れ、weighting が期待どおり掛かることを**1 本ずつ**確認する
  自前の検証信号が要る。落ちるチャンネルがあれば合計が下振れするので、単独入力なら必ず検出できる。
- 5.1 / 7.1.4 が Annex 3 のどの configuration に当たるかで、-4 と -5 の数値差が出るかが決まる
  （findings §7）。ここが未確認のまま 7.1.4 の数値を確定させない（R-11）。

## 3. やらないこと

- **Atmos メタデータの読み取り。** 通常の音声バスからは取得しない（findings §6.3）。
- **Atmos 納品適合の判定。** 数値条件（−18 LKFS / −1 dBTP）が分かっても、
  測定経路が確定していない（findings §7）。任意の 7.1.4 出力やバイノーラル出力を測っただけで
  「適合」と表示しない。
- **最新版だから BS.1770-5 準拠、という表示。**

## 4. 決定点（順に / 一括では出さない）

いま要るのは 1 だけである。

1. **Phase S-0 → S-1 → S-2 まで進めてよいか。** 推奨は「進める」。
   外部資料に一切依存せず、5.1 まで実測 gate 付きで閉じられる。
2. ABI の最大チャンネル数を 16 で確定してよいか（S-1 着手前）。
3. S-4 の置き換え内容（S-2 完了後）。
4. 7.1.4 の着手可否（BS.2051 角度表の入手後）。

## 5. 各 Phase 共通の規律

- **R-9**: 実装前に対象ファイルを全部読む。map テーブルは規格の実文ではなく、
  JUCE と `vendor/ebur128` の**実際の定義**に当てて書く。
- **R-10**: ABI サイズ、weighting の効き、欠落チャンネルの有無は、すべて数字で確認する。
  概算のまま invariant に書かない。
- **R-11**: 角度・configuration・downmix 係数は記憶で書かない。一次資料が無い間は未確認と明記する。
- **negative check**: guard を足したら必ず壊して落ちることを確認する。
  本セッションで 2 回、「テスト経路 ≠ 出荷経路」で guard が死んでいた（B-917 / B-923）。
- **構造的対処**: `channels == 2` の 17 か所は一括で処理する。1 画面 / 1 か所ずつ直さない。
