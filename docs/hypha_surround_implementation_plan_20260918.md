## 2. 誤差方向を下振れに限定できない（訂正 #1 の根拠）

固定窓の非ゲート・エネルギー和なら、正の重みの項を落とせば増えない。
しかし Integrated Loudness は入力から決まる絶対ゲート（−70 LKFS）と相対ゲート（−10 LU）を使う。
**欠落した信号によって、平均に採用される時間区間そのものが変わる。**

以下はゲートの性質を示す解析上の例であり、Hypha の測定結果ではない。

- 全ブロックの 10% に、**保持される**チャンネルだけの −20 LUFS。
- 残り 90% に、**欠落する**チャンネルだけの −35 LUFS。
- 正しい全チャンネル: 非ゲート平均 −28.9125 LUFS、相対ゲート −38.9125 LUFS。両群とも採用される。
- 欠落すると、その 90% は無音として絶対ゲートで除外され、残るのは −20 LUFS。
- **誤った値が約 +8.91 LU 大きくなる。**

一方、7.1.4 の非 LFE 11 本に等しい定常エネルギーを入れる単純モデルでは、
正しい重みの和 9 + 2×1.41 = 11.82、既定 map では 3 + 2×1.41 = 5.82 で約 −3.08 LU。

**どちらも条件を限定した説明用の計算であり、固定補正値にしてはいけない。**
防止手段は補正係数ではなく、正しい明示 map と入力経路の検証である。

## 3. 本セッションで新たに確認した実装上の事実

### 3.1 レイアウトは FFI を越えられない [A]

```
crates/kirin_hypha_ffi/include/kirin_hypha_ffi.h:502
KirinHypha* kirin_hypha_create(uint32_t sample_rate, uint32_t num_channels);
```

**create が受け取るのは rate とチャンネル数だけで、レイアウトを渡す口が無い。**
明示 map を作るだけでは足りず、**FFI の入口そのものを変える**必要がある。

### 3.2 エンジン再生成はチャンネル数だけを見ている [A]

```
juce_shell/src/PluginProcessor.cpp:123-125
const bool needsNewHandle = hyphaHandle == nullptr
                         || std::abs (preparedSampleRate - sampleRate) > 0.001
                         || preparedInputChannels != numCh;
```

**同数の別レイアウト（7.1.2 ⇄ 5.1.4、7.1 ⇄ 5.1.2）では再生成されない。**
音声側だけが新しい配置になり、測定側は古い map のまま残る。

さらに直後（`PluginProcessor.cpp:128-129`）で、Record 中は非互換 reprepare を延期する（B-334）。
Stop 権限を勝手に移さない既存規律は正しいが、**その間、新しい音声が古い map の測定器へ入る**。

`set_channel_map` の再呼び出しはこの契約の代わりにならない。
`vendor/ebur128/src/ebur128.rs:425` は map 配列を更新するだけで、既存履歴を新しい意味へ変換しない。

### 3.3 `[2]` を一律に広げてはいけない [A]

`clip_event_count[2]` は**入力チャンネル**である（`kirin_hypha_ffi.h:163` に `0=L, 1=R` と明記）。

一方 `KirinReferenceCaptureUnit`（`kirin_hypha_reference_index_ffi.h:9`）の `rms[2]` / `peak[2]` は
Reference 側の値で、同ヘッダ末尾に

```
static_assert(sizeof(KirinReferenceCaptureUnit)==64,"Capture index storage contract");
```

がある。**これは capture index の保存形式の契約**であり、`[2]→[16]` にすると 64 → 176 バイトになって
保存形式と `kirin_reference_index_compare` の意味が変わる。

**意味を確認せず全 `[2]` を置換しない。** 初版の「8 本 + 3 本」は棚卸しの入口であって確定数ではない。

### 3.4 7.1.4 map は vendor の実装と整合する [A]

[B] の割り当て（side = M±090、rear = M±135、上方 = U±045 / U±135）に対し、
`vendor/ebur128/src/ebur128.rs` は `Mp090` `Mm090` `Mp135` `Mm135` `Up045` `Um045` `Up135` `Um135` を
すべて持ち、`filter.rs:352` の ×1.41 対象は
`{LeftSurround, RightSurround, Mp060, Mm060, Mp090, Mm090}` である。

したがって **side = 1.41、rear = 1.00、上方 = 1.00** がそのまま出る。vendor 実装と矛盾しない。

## 5. 実装前に成立させる共通契約

### 5.1 レイアウト記述を単一の正本にする

JUCE の enum 値をそのまま Rust へ渡さない。安定した独自 ABI enum と検証済みレイアウト記述を作る。

採用候補の項目（名前は既存規約に合わせる）: `layout_id` / `channel_count` / `channel_positions[]` /
`layout_revision` / `mapping_revision` / `layout_fingerprint`。

同じ意味定義を、ホスト交渉・バッファ処理・エンジン生成・ピーク配列・相関ペア・画面ラベル・
Record・Reference 比較・PRE/POST 比較のすべてへ渡す。

C++ と Rust に無関係な 2 つの手書き table を作らない。
**ただし、テストの期待値を製品 table から自動生成するだけでは同じ誤りを共有するので不十分。**

### 5.2 検証をホスト交渉だけに置かない

`isBusesLayoutSupported` の拒否は必要だが、FFI 直呼び・テスト専用生成・ファイル解析経路を守れない。

エンジン生成時にもチャンネル数・各位置・重複・バッファ寸法の整合を検証し、
**検証を通った記述なしでは測定エンジンを生成できない形**にする。
未対応時に既定 map へ戻さない。LFE 以外の `Unused` で穴埋めして生成を成功させない。

map の適用は**エンジン構築の内部**に閉じる。最初のサンプル投入前・最初のキャッシュ照会前に成立させる。
生成後に呼び忘れ得る必須操作として外へ露出させない。

R-28 との関係: 利用者操作への失敗表示と内部処理の自動失敗は区別する。
静かな失敗でも、**有効な測定値に見せないことは必須**である。

### 5.3 測定区間（epoch）を設計する

§3.2 の 2 つの事実から、`preparedLayout` を足すだけでは足りない。

1. 測定区間に `measurement_epoch` 相当を持たせ、レイアウト / map / rate / 測定方式の変更で区切る。
2. 同一形式の再 prepare、ブロック長変更、通常の offline bounce では既存の Record 保持規律を壊さない。
3. 非互換変更を適用できない間は、**新しい音声を古い map の測定器へ投入しない。**
   測定不能または中断として記録し、音声 A の通過は維持する（R-12）。
4. Record の停止権限を勝手に移さない。既存 writer の最終化と新 epoch の開始規則を先に明文化する。
5. I / LRA / 最大値 / 時系列 / キャッシュ / PRE-POST delta に区間をまたいだ混在がないことを確認する。

### 5.4 測定メタデータを先に分離する

| 分類 | 記録する内容 | 推測しないこと |
|---|---|---|
| 入力の事実 | negotiated layout、順序、実チャンネル数、sample rate | 12ch だから 7.1.4 と決めない |
| 実際の測定 | 適用 map、profile ID、mapping revision、epoch | 同じ GUI 設定名だから同じ処理とみなさない |
| 実装版 | Hypha commit / build、crate version、vendor patch 識別 | `ebur128 0.1.10` の文字列だけで独自修正を隠さない |
| 規格参照 | loudness / peak / layout 各処理の参照資料と版 | Apple の指定版と実装プロファイルの版を混ぜない |
| レンダリング条件 | renderer、出力配置、モード、取得方法 | 取得していない情報は unknown。自己申告は自己申告として区別 |
| 観測位置 | renderer 前 / 後 / 不明 | Hypha の PRE / POST を Atmos renderer の前後と同一視しない |
| 証拠 | 試験セット、期待値出典、実施環境、結果 artifact | 規格名だけを「準拠試験済み」の代用にしない |

BS.1770-5 Annex 4 は、レンダリング後に測る方式と、**使用した配置とレンダリング方法の報告**を扱う [B]。
外部 renderer の出力測定は可能だが、未知の renderer の情報までプラグインが保証するわけではない。

### 5.5 ABI は「配列を増やす変更」より広い

推奨は固定最大 16。ただし次をセットで変更する。

- `channel_count` の意味と範囲を定義し、**配列の容量**と**製品の対応配置**を区別する。
  **16 は容量であって 9.1.6 対応の宣言ではない。**
- Observatory frame version を含む版管理を更新し、ABI / schema / struct_size を照合する。
  旧 Rust staticlib と新 C++ shell の混在を拒否する。
- `sizeof` だけでなく `alignof` / `offsetof` / 整数幅 / padding / 配列 stride を Rust と C++ で照合する。
- 旧 state / Record / 保存データの読み取り方針を決める。旧データを新しい Nch 値として捏造しない。
- 未使用領域は double = NaN、整数 = 0。ただし **0 だけでは「未測定」と「測定済みのゼロ」を
  区別できない**ので `count` / `status` / validity と併用する。
- NaN を含む等値判定は意味ベースで扱う。NaN の `==`、padding を含む `memcmp`、
  JSON の素の数値としての NaN 保存を前提にしない。

初版の「1008 → 約 1808 / 1248 → 約 2048 / +798」は**概算であり、本監査の実測値ではない。**
承認資料の確定値から外す。

### 5.5.1 取込容量は ABI 容量とは別の課題

> 取込容量は ABI 容量とは独立した P-0 の設計課題とする。
> 現行の 384 MiB 契約を単純に Nch へ線形拡張することは、まだ採用しない。
> まず現行容量を構成する各保持領域と allocation lifecycle を実測・分類し、
> 5.1 および 7.1.4 で現行の同時 pair 数・burst・pre-roll 保証を維持した場合の上限を算出する。
> その結果を基に、(a) 現行保証を維持したまま保持構造を変更、(b) RSS 予算を変更、
> (c) 明示的に同時利用条件を変更、の順で検討する。
> **利用条件の縮小は Daisuke の承認なしに行わない。**

分解と lifecycle は `@docs/hypha_surround_ingest_capacity_20260918.md`（B-929）。
**16ch という ABI のスロット容量を、audio retention の設計思想へ持ち込まない。**

## 6. 5.1 公開前に、全計測の意味を確定する

「ラウドネスだけ Nch、その他は先頭 2ch を暗黙に使用」を禁止する。
各指標について、入力対象・計算・出力単位・有効条件・レイアウト変更時のリセットを表にする。

| 指標群 | 推奨する扱い | 禁止 |

| Sample Peak / True Peak / Clip / VU | チャンネル別値とラベルを対応。LFE のピークは別途観測 | LUFS 除外を理由に LFE のピーク観測まで落とす |

| MONO / MID-SIDE / Stereo Field | ステレオでは意味を維持。多 ch では明示ペアに限定するか適用外と示す | ラベルを維持したまま全体値へ意味変更 |

| Zwicker / Sharpness / PSB | 現行入力合成を調べ、Nch での意味を別途確定 | チャンネル別値の単純和を「サラウンドの知覚値」と宣言 |
| Reference A/B / PRE-POST delta | 適合条件・ステレオ Reference の扱い・変換条件を明示 | stereo と 7.1.4 を同じ尺度の比較として自動提示 |

この表は設計提案であり、現在の各指標の内部処理をすべて確認したという意味ではない [C]。

初期公開で適用外のモジュールがある場合は理由を明示する。
**ただしこれは、要求を無断で後回しにする許可ではない。**
全機能置換を同時公開するか、適用外を明示した段階公開にするかは Daisuke が決める。

## 7. Correlation / Balance / Downmix の再設計

### 7.1 Correlation

5.1 の L/R・Ls/Rs、7.1.4 の 5 つの左右対は常設 overview として妥当。
ただし L と C、L と Ls、上方と下方など、**同じ downmix 出力へ合流する別の組合せを見落とす。**

12ch の独立ペアは 66、16ch で 120。UI が不可能とは言えない。
推奨は「左右対 overview + 選択ペア詳細」。全組合せ表示の採否は UI 試作で決める。

**Halo Vision は全チャンネル間の Correlation Matrix / Correlation Web と、
レベル差を考慮する Contextual Correlation を持つ [B]。**
従来の正規化相関を数本出すだけでは競合を超える根拠にならない。

相関係数だけで位相打ち消しの大きさを説明しない。
同じ −1 でも、2 入力のレベル差で合流後の残り方は違う。
窓長・DC の扱い・分母ゼロ時の状態・ペアの身元を含めて定義する。
無音時を「0 ＝無相関」と自動表示しない。

### 7.2 Balance

採用候補: 非 LFE の左右グループについて同じ時間窓のエネルギー `E_L` / `E_R` を求め、
`10*log10(E_L/E_R)` を左右エネルギー比として記録する。
**これは独自の観測定義であり、ITU のラウドネスそのものではない。**

中央と LFE は左右グループから除く。両側無音は適用値なし、片側のみは left-only / right-only。
BS.1770 の重みを使うか非加重の物理エネルギーにするかを混ぜない。**推奨は後者を基本にし、名称に明記する。**

### 7.3 Downmix — 初版のままでは測定量が決まっていない

「何が残るか」には、係数による減衰・意図的なチャンネル除外・信号間干渉・ラウドネス変化があり、
**一つの「生存率」にまとめてはいけない。**

以下は設計を詰めるための数式案であり、既存規格の定義でも実装済み機能でもない。
入力 `i`、出力 `j`、帯域 `b`、明示 downmix 係数 `a[j,i]`、同じ帯域処理・時間窓で:

```
y[j,b]      = Σ_i a[j,i] * x[i,b]
P_out[b]    = Σ_j mean(y[j,b]^2)
P_diag[b]   = Σ_j Σ_i a[j,i]^2 * mean(x[i,b]^2)
D_interference[b] = 10*log10(P_out[b] / P_diag[b])
```

`P_diag` は交差項を除いた基準なので、この比は**同じ係数の下での信号間干渉**を示す。
完全相殺なら −∞、同相の合流では正値もあり、基準エネルギーがゼロなら未定義。
等しい同相 2 信号で +3.0103 dB、等しい逆相で完全相殺。

入力全体に対する**残存エネルギー**を見たい場合は `P_in` の対象を別に定義して `10*log10(P_out/P_in)`。
この値は係数の増減や捨てたチャンネルにも影響される。**干渉差と残存エネルギー比を同一視しない。**

この区別なしに既存 MONO の 0..−24 dB スケールを流用すると、正値をクリップする、
無音と完全相殺を混同する、LFE 除外を「位相問題」に見せる、といった誤表示になる。

**承認条件**: 係数行列 / 入出力配置 / LFE の扱い / 振幅係数か電力係数か / 正規化 / 帯域フィルター /
窓 / 時間合わせ / 分母ゼロ / −∞ / 表示上下限 / 履歴・Record の意味 を一つの定義にする。
係数は出典と版を記録する。**未確認の係数を記憶で埋めない（R-11）。**
最初は外部レンダラーの再現を名乗らず、明示的な観測用行列で数学的性質を検証する。

R-12: 内部 downmix は観測のためだけに計算し、入力 A の出力音声は変更しない。

## 8. Phase

P-番号は本書内の工程識別子で、既存の R 番号・B 番号とは無関係。
各 Phase の「gate」は次へ進むための内部検証条件であり、音源の良否や納品適合の判定 UI ではない。

### P-0 — 事実の訂正と全体契約の固定

findings を §1 の訂正で更新する。変更対象全ファイルを通読する。
`channels == 2` だけでなく `[2]` / L/R 固定名 / interleave / stride / state / FFI / Reference /
心理音響 / Record / UI / ペアリングを棚卸しする。

成果物: 根拠つき map 定義、全指標の適用表（§6）、入出力レイアウト契約、ABI 方針、
epoch / Record 遷移表、公開対象の定義。

**gate**: 各出力項目の入力対象と有効条件が決まっている。容量 16・初回公開範囲・
Record 中の変更方針が承認されている。未確認を確認済み欄へ移していない。

### P-1 — 検証済みレイアウトだけでエンジンを作る

独自レイアウト記述と中央の検証処理を作る。**`kirin_hypha_create` の signature を変える**（§3.1）。
まず mono / stereo を新経路へ移し、同じ経路に 5.0 / 5.1 / 7.1.4 を定義する。
**公開ホストの受理範囲はまだ増やさない。**

**gate**: 不正・重複・未知・count 不一致・LFE 以外の欠落を拒否する。
mono / stereo の既存値と出力音声が回帰しない。
**出荷用コンストラクターを通る試験で、map 適用を外す変異が検出される。**

### P-2 — ABI・観測状態・記録を同時に Nch 化する

最大 16、count、位置情報、版、validity、epoch を必要な ABI へ導入する。
**入力チャンネルを意味する配列だけを**拡張する（§3.3）。
`KirinReferenceCaptureUnit` の 64 バイト保存契約は別問題として扱う。

**gate**: Rust / C++ のサイズ・offset・alignment が**実測で**一致する。旧 staticlib との組合せを検出する。
全 16 スロットへ異なる識別値を入れた往復で位置が一致する。count 以降を表示・保存・集計しない。
意味を持つ 0 と未測定を区別する。

### P-3 — レイアウト変更・測定区間・Record の状態機械

再生成条件へ layout fingerprint を追加する（§3.2）。
同数別配置 / rate 変更 / Record 中 / offline bounce / state restore / 再 prepare /
PRE・POST の片側変更を扱う。無効期間の測定欠落を記録し、古い有効値を現在値として残さない。

**gate**: 10ch の 7.1.2 と 5.1.4、8ch の 7.1 と 5.1.2 を区別できる。
未対応のままにする場合も拒否が正しく働く。
対応構成の変更時は epoch が分かれ、I / LRA / peak / history が混在しない。
Record の既存停止権限と同一形式の継続を壊さない。

### P-4 — 5.0 / 5.1 の全経路

ステレオ専用処理を §6 の契約で処理する。個別ピーク・ラベル・履歴を通す。
EBU の 5ch / 6ch fixture を**明示 map から**測る。

**gate**: EBU Tech 3341 の対応ケースが規定許容差で一致（case 6 は I = −23.0 ± 0.1 LUFS）[B]。
**ただしこれだけで完了しない。** L/R/C/Ls/Rs の身元、LFE のラウドネス除外とピーク観測、
チャンネル別 clip、Record への保存を独立試験で確認する（訂正 #4）。

### P-5 — 出荷経路の検証

対象 commit の CMake で構成される形式を基準に公開対象を確定する。
SDK やホストを用意していない形式は**未試験と記録する**。

**gate**: host → wrapper → JUCE buffer → FFI → Rust → poll → UI / Record の全経路で、
個別信号の身元が一致する。ホストがレイアウトを提供しない場合は「未対応」とし、
discrete への無言フォールバックで成功扱いしない。
RT / offline / 大小ブロック / 可変ブロック / 複数インスタンスで整合する。

**公開条件**: P-0〜P-5 の証拠が揃った範囲だけを 5.0 / 5.1 対応として公開する。

### P-6 — 7.1.4

§4.2 の 12 本を 1 本ずつ入力し、ラウドネス寄与・peak・ラベル・保存先を確認する。
AU / VST3 の内部順変換を含め、P-5 の検証を 7.1.4 で再実施する。

**gate**: 全 12 本の身元と全 11 本の非 LFE 寄与が一致する。
side = 1.41 / rear = 1.00 / upper = 1.00 が**独立期待値**で一致する。
同重み入れ替え、rear を surround へ誤指定、上方を `Unused`、LFE を加算、の各変異が検出される。

**「table に 1 行追加で済む」は望ましい設計結果であって、検証を 1 行分に縮める理由ではない。**
容量 16 があっても 9.1.6 を自動的に有効にしない。

### P-7 — downmix 観測

§7.3 の定義から採用する量を承認し、係数・プロファイル・表示を固定する。
既存 MONO の意味を残すか名前を変えて移行するかを明示する。

**gate**: 同相 / 逆相 / 独立 / レベル差 / ゼロ入力 / 係数ゼロ / チャンネル除外 / 遅延差で
数学的期待値と一致する。正値 / 負値 / −∞ / 未定義を区別し、音声 A の bit-identical 通過を維持する。

## 9. 試験の規律

### 9.1 期待値の独立性

製品 map → テスト map → 期待値を**すべて同じ関数から生成しない**。
規格に基づく固定期待値、テスト信号のチャンネル識別、独立した参照実装、実際の出荷バイナリを区別する。

### 9.2 必須の negative check

① 非 LFE を `Unused` へ変更 / ② **同じ Gi の 2ch を交換** / ③ LFE を加算 /
④ rear を 1.41 へ変更 / ⑤ **出荷コンストラクターの map 適用を削除** /
⑥ 同数配置変更時に旧 engine を再利用 / ⑦ count 外の要素を表示 / ⑧ 旧 ABI サイズ・版を混ぜる。

**② は LUFS 合計では検出できない。⑤ は製品コードを通らないテストでは検出できない。**
「試験用 table を壊したら試験が落ちた」で終えず、**出荷経路の不変条件**を壊して落ちることを確認する。
変異は隔離環境で行い、壊した実装を本体へ残さない。

### 9.3 実行証拠

各 gate に、対象 commit / OS / DAW と版 / プラグイン形式 / sample rate / block 条件 /
fixture の hash / layout・map / 期待値出典 / 許容差 / 実測値 / コマンド / 合否 / negative check 結果を添付する。

過去の件数をそのまま現在の合格数にしない。

## 10. やらないこと

- Atmos メタデータの読み取り。
- **Atmos 納品適合の判定。** 任意の 7.1.4 出力やバイノーラル出力を測っただけで「適合」と表示しない。
- 最新版だから BS.1770-5 準拠、という表示。
- チャンネルベースの測定と、Atmos 納品ファイル全体の適合検証を同じものとして扱うこと。

## 11. 承認点

### 11.1 最初に求める承認

**P-0 の契約確定と、mono / stereo の公開挙動を変えない P-1 の防御実装まで。**
初版 S-0〜S-2 の一括承認は、ABI・Record・指標定義が未確定なので避ける。

### 11.2 実装前に確定させる 3 件

1. **容量 16、対応配置は別管理**という方針を採るか。推奨は採用。
   容量の決定を ABI 実装の後へ残さない。
2. **非互換レイアウト変更中は測定を保留し、旧 map へ新音声を入れない**方針と、
   Record の区切り・再開権限。推奨は採用し、既存 Stop 権限を維持。
3. **初期公開で適用外を明示するモジュールを認めるか、全機能置換と同時公開か。**
   未定義値を表示しない点は共通の必須条件。

downmix の新しい量・名称・表示範囲は P-7 着手前に別途承認する。
これは資料待ちではなく、**測定量そのものを決める必要がある**ためである。

### 11.3 残っている情報不足 [C]

- 各対応 OS / DAW / 形式での実測、全関連ファイルの通読、Reference・心理音響の正確な入力経路、
  ABI サイズ・レイアウト、RT 負荷、データ互換性。
- Dolby の専用 loudness 測定経路の公式本文（取得失敗）。
- 採用する downmix 係数の正式出典。
- EBU v05 全 70 ファイルの header 走査（訂正 #13）。

**解消済みで、以後「資料待ち」の理由に使わないもの**: BS.2051-3 の 7.1.4 配置表、
BS.1770-5 の対応表、対象 JUCE のチャンネル集合・列挙・型番号。

## 12. 評価

初版の正しかった部分は、無言欠落の防止、推測 map の拒否、明示的な測定条件、
出力音声を変えない観測という方針である。ここは維持する。

**誤っていたのは「map が正しければ製品の意味も正しい」という飛躍である。**
数値の生成、各チャンネルの身元、時間区間、Record、比較対象、表示する指標の定義が揃わなければ、
LUFS だけ正しくても観測システムとしては誤る。

優先順位は **測定の身元と区間 → 明示 map → ABI と全指標の意味 → 出荷経路試験 →
対応レイアウト公開 → 新しい downmix 観測**。相互依存する契約は P-0 で同時に設計し、
機能を後付けのパッチで広げない。

差別化候補は「チャンネル数の多さ」でも「相関を数本出すこと」でもない。
**どの入力・どの map・どの区間・どの変換条件からその観測値が得られたかを、
UI・Record・Kirin OS への引き渡しまで追跡可能にすること**である。
帯域別 downmix 観測は、その基盤の上で測定定義と試験が成立したときに初めて独自価値になる。
